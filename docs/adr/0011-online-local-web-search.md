# ADR 0011: 데이터 사용 ON/OFF와 웹검색

- 상태: 채택
- 날짜: 2026-09-09
- 마이그레이션: `0012_network_search`

> 2026-09-12: 문맥 검색 활성화 시의 전송 범위·반복 상한·모델 사용량 정산은 [ADR 0014](0014-bounded-context-search-and-step-usage.md)로 확장했다. 설정 화면은 데이터 사용 ON/OFF 하나로 정리했다. 아래 단일 검색의 전송 범위와 당시 마이그레이션 이력은 초기 구현 기록이며, 화면·요청 계약은 현재 정책을 반영한다.

> 2026-09-12 검색 조건 보정: 데이터 사용 ON을 강제 검색 `web_search=on`에 연결하던 화면 요청을 `auto`로 수정했다. 서버의 기존 키워드 판단 함수는 유지한다. 아래 현재 계약을 따르며 당시 검증 기록은 별도로 보존한다.

## 배경과 결정

모델과 DB가 이 Mac에 있으므로 모델·패키지 설치 후에는 인터넷 없이도 로컬 채팅을 사용할 수 있다. 인터넷을 사용할 수 있으면 최신 자료를 검색하고, 사용할 수 없으면 기존 로컬 답변을 유지한다. 사용자는 외부 통신을 명시적으로 끌 수 있어야 한다. 웹 서버의 같은 Wi-Fi/LAN 접속 범위와 FastAPI·PostgreSQL·모델 서버의 loopback 바인딩은 유지한다.

사용자별 `local_only` 기본값은 false이며 화면에서는 데이터 사용 ON으로 표시한다. 데이터 사용 ON은 `local_only=false`, OFF는 `local_only=true`에 대응한다. ON이고 검색 서비스에 도달할 수 있으면 온라인, 연결할 수 없거나 키가 없으면 로컬 모드로 표시한다. OFF이면 외부 연결 검사와 검색을 차단한다. Wi-Fi 인터페이스 연결 여부와 실제 인터넷 사용 가능 여부는 다르므로 브라우저 `navigator.onLine`이나 물리 Wi-Fi 상태를 판정 근거로 사용하지 않는다. 모델 추론은 어느 모드에서도 로컬에서 수행한다.

기본 공급자는 사용자 선택에 따라 Tavily Search API로 정한다. `WEB_SEARCH_PROVIDER=tavily`가 기본이고 `brave`는 선택 어댑터로 유지하며 `disabled`로 서버 전체 검색을 끌 수 있다. 선택한 공급자의 발급 키는 서버용 `.env`의 `WEB_SEARCH_API_KEY`에만 보관하고 `SecretStr`로 읽는다. 키가 없어도 로컬 로그인·대화·생성은 사용할 수 있다. 실제 요금·요청 한도는 공급자 계정의 계약을 따른다.

초기 구현의 Brave 어댑터와 저장된 `provider=brave` 출처는 보존하고 기본 공급자만 Tavily로 변경한다. 별도의 DB migration이나 과거 검색 이력 변환은 필요하지 않다. Brave를 선택할 때에만 [공식 결과 저장 안내](https://brave.com/search/api/)에 따른 저장 권한 계약을 확인한다. 이 조건을 기본 Tavily 사용에 대한 조건으로 적용하지 않는다.

## 설정·요청·저장

`user_preferences`는 사용자 UUID를 키로 `local_only`, 변경 revision, 갱신 시각을 저장한다. 설정 변경은 사용자 행을 잠가 생성 승인과 직렬화한다. 값이 바뀔 때 revision을 증가시킨다. 일반 사용자와 system 계정 모두 자신의 외부 통신 설정만 변경할 수 있고, system의 토큰 면제가 외부 통신 권한을 확대하지 않는다.

`GET /api/v1/network-mode`는 인증 후 설정과 연결 상태를 반환한다. `PATCH`는 `{local_only}`를 저장하며 `POST /api/v1/network-mode/check`는 JSON `{}`로 재확인한다. 쓰기에는 기존 CSRF·Origin 검사를 적용한다. 상태에는 `local_only`, `revision`, `mode=local/online`, `reason=forced_local/provider_unconfigured/offline/available`, `search_configured`, `checked_at`을 포함한다. GET도 저장된 정책과 캐시에 따라 공급자 연결을 검사할 수 있으며 로컬 전용에서는 어떤 경로도 외부 검사를 하지 않는다.

새 질문과 재생성은 생성 `options` 외에 최상위 `network_mode=auto/local`, `web_search=auto/on/off`를 받는다. 웹 화면의 데이터 사용 ON은 `network_mode=auto`, `web_search=auto`로 요청한다. OFF와 설정 조회·재확인·저장 중, 설정 오류 때는 `network_mode=local`, `web_search=off`로 보낸다. 이어 쓰기와 질문 카드 응답에도 같은 정책을 적용한다. 서버에 저장된 로컬 전용 설정이 요청보다 우선한다. 동일 요청 키의 모드까지 멱등성 비교에 포함한다. `generation_runs`는 승인 당시 적용 모드·검색 방식·revision을 기록한다. 기존 생성 이력은 migration에서 `local/off`로 보존하므로 새 기능 도입으로 과거 질문이 외부에 전달되지 않는다.

화면은 데이터 사용 ON/OFF만 제공하며 별도 웹검색 선택이나 검색 방식 저장 상태를 두지 않는다. ON은 필요한 질문에 검색을 허용하는 정책이다. 서버의 기존 자동 규칙이 검색 대상으로 고른 뒤 모델의 검색 계획, 문맥·사용량 한도, 공급자 연결 상태를 확인하며 검색을 수행하지 못하거나 자료를 채택하지 못하면 기존 로컬 답변으로 전환한다. 서버의 요청별 `auto/on/off` 계약과 승인 당시 적용 정책 기록은 유지해 기존 클라이언트·재생성·대기 작업의 의미를 보존한다.

`web_search_runs`는 생성별 하나의 검색 상태·사유·공급자·정규화된 출처 목록을 저장한다. 출처는 번호, 제목, URL, 요약, 조회 시각을 포함한다. 생성·메시지 조회와 SSE의 기존 접근 권한을 통해서만 제공하며 별도 공개 검색 기록 API는 만들지 않는다. 이전 답변 버전의 검색 근거도 보존한다.

## 검색 실행과 문맥

자동 검색의 첫 판단은 `tools/web_search/context.py`의 `should_search` 키워드 규칙이다. 검색 키워드가 없는 인사·기초 개념·단순 번역·계산은 검색 준비와 외부 검색을 생략한다. 명시적인 검색 요청이나 최신 뉴스·날씨·환율 등은 검색 대상으로 고르며, 사용자의 검색 금지와 로컬 전용 정책을 먼저 적용한다. 이 선별 이후의 문맥 검색·재검색 계획은 기존 실행 경로를 사용한다.

키워드 규칙은 모든 질문의 의미를 구분하지 못한다. 예를 들어 “오늘 날씨가 좋다를 영어로 번역해 줘”는 번역 요청이어도 최신 정보 키워드 때문에 검색 대상으로 잘못 분류될 수 있다. 이번 보정은 ON의 강제 검색 연결을 해제한 것이며 모든 질문을 이해하는 새 의미 판별 모델을 구현한 것은 아니다. 설정 조회·수동 재확인의 공급자 연결 검사는 질문별 외부 검색과 별도다.

독립 worker는 필요하면 기존 대화를 압축하고, 검색이 필요한 질문에 대해 모드·revision을 확인한 뒤 자료를 수집한다. 기본 문맥 검색은 현재 질문과 최근 사용자 발언 4개에서 필요한 원문 표현을 골라 최대 500자의 검색어를 만들며, 과거 발언에서 고른 표현은 합계 80자로 제한한다. 문맥 검색을 끄거나 도구 호출 미지원 공급자를 쓰면 현재 질문 앞부분 최대 500자를 사용한다. 전체 대화·압축 요약·전체 모델 입력은 검색 서비스에 전송하지 않는다. 기본 최대 5건, 검색 시간 제한 8초, 연결 검사 제한 2초, 연결 확인 캐시 30초, 검색 문맥 글자 상한 12,000자를 사용한다. 이 값은 환경 설정으로 관리한다.

현재 범위는 검색 API가 반환한 제목·요약·링크다. 검색 결과 URL의 페이지 본문을 직접 가져오거나 JavaScript를 실행하지 않는다. `provider.py`의 공통 규격과 `adapters/tavily.py`, 선택 `adapters/brave.py`, 공통 정규화 `adapters/common.py`를 분리해 공급자 교체가 모드·정산·저장 코드를 바꾸지 않도록 한다. 응답 크기와 시간을 제한하고 URL을 정규화하며 중복을 제거한다.

Tavily 요청은 `search_depth=basic`, `auto_parameters=false`로 고정해 상위 검색으로 자동 전환하지 않는다. `include_answer`, `include_raw_content`, `include_images`는 모두 false로 보내 외부 답변 생성·원문 본문·이미지를 요청하지 않는다. 검색 자료를 바탕으로 최종 답변하는 책임은 로컬 모델에 유지한다. 요청 규격은 [Tavily 공식 검색 API](https://docs.tavily.com/documentation/api-reference/endpoint/search)를 따른다. 화면의 데이터 사용 ON과 Tavily의 자동 파라미터 설정은 별개이며, ON으로 바꿔도 이 고정 검색 옵션은 유지한다.

검색 자료는 출처 번호가 있는 비신뢰 참고 기록으로 모델 문맥에 넣는다. 자료에 포함된 명령을 실행하거나 상위 지침으로 취급하지 않도록 안내한다. 실제 tokenizer로 입력을 다시 계산하고 문맥·사용자 허용량을 지키도록 자료 수와 출력 상한을 조정한다. 넣을 수 없으면 검색 자료를 생략하고 그 사실을 알린다. 출처를 표시하는 코드는 보장할 수 있지만 모델이 실제 주장을 올바른 출처에 대응시키는지는 별도의 의미 평가 대상이다.

실제 답변의 검색 자료 포함 입력과 출력은 기존 완료·중단 후 정책으로 한 번 정산한다. 생성 전에 토큰을 예약·차감하지 않으며 검색 요청 자체를 사용자 LLM 토큰으로 청구하지 않는다. 검색 API 비용은 공급자 계약과 별개로 관리한다. 자동 압축에 사용한 요약 토큰은 계속 시스템 유지 작업으로 기록하고 사용자 한도에서 차감하지 않는다.

## 중단·오프라인·화면

데이터 사용 OFF(`local_only=true`)와 요청의 `local`은 외부 연결 검사·검색보다 먼저 적용한다. 승인 후 설정 revision이 달라지면 진행 중 요청을 취소하고 후속 외부 요청을 보내지 않는다. 대기 중 작업도 실행 시 다시 검사한다. 설정 변경으로 검색이 중단되면 질문을 보존하고 로컬 답변으로 전환한다. 답변 중단 버튼은 기존 전체 생성 취소이며 검색 단계에서도 동작한다.

연결 실패·시간 초과·잘못된 인증·공급자 제한·빈 결과에서는 원본 질문과 실패 사유를 보존하고 로컬 답변을 시도한다. 최신 자료를 확인하지 못했다는 문맥 지시와 화면 안내를 제공한다. 로컬 답변도 모델이나 토큰 한도 오류가 있으면 기존 오류 정책을 따른다. 오프라인 전환은 사용자가 저장한 데이터 사용 ON/OFF를 변경하지 않는다. ON 상태라면 후속 질문이나 수동 확인에서 다시 온라인으로 돌아갈 수 있다.

화면은 초기 조회와 수동 재확인을 사용하고 자동 폴링하지 않는다. 검색 결과 메타가 도착하면 상단 온라인/로컬 표시도 반영하되 사용자 설정과 revision은 덮어쓰지 않는다. `검색 중`, `정리 중`, `생성 중`의 간단한 상태는 구분하되 본문의 진행 계획·처리 과정 목록은 표시하지 않는다. 내부 생성 단계·SSE·사용량 정산은 유지한다. 답변 아래 참고 자료는 기본으로 접어 두고 클릭하면 아래로 펼쳐 제목 링크만 표시한다. 검색 요약 본문과 조회 시각은 목록에 표시하지 않는다. 이는 화면 표시만 바꾸는 것으로 DB/API의 `snippet`·`retrieved_at`과 모델 참고 문맥은 유지한다. raw HTML과 외부 이미지 자동 로드를 허용하지 않고, 출처 링크는 사용자가 선택했을 때만 연다. 기존 grapheme 타이핑·즉시 중단·사용자 스크롤 우선·복사·이전 버전 보존을 유지한다.

## 통신 경계와 제한

서버는 선택한 공급자의 고정 HTTPS API(Tavily 또는 Brave)만 호출하고 redirect를 자동 추적하지 않는다. 사용자 쿠키·세션·인증 헤더는 외부로 전달하지 않는다. API 키·검색어·응답 원문은 일반 오류와 로그에 노출하지 않고 정해진 오류 코드로 기록한다. 검색 결과의 위험한 URL과 HTML을 걸러도 실제 모델의 prompt injection 저항성을 증명한 것은 아니므로 실제 모델 평가를 별도로 남긴다.

향후 임의 페이지 본문 수집을 추가할 때는 DNS 해석 결과와 모든 redirect의 사설망·loopback·link-local·metadata 차단, MIME/크기 제한, 관련 본문 선택을 먼저 구현해야 한다. 현재는 임의 URL을 서버가 방문하지 않으므로 이 범위를 이미 완료한 것으로 표시하지 않는다.

## 검증·적용·롤백

가짜 HTTP 공급자와 모델, 격리 PostgreSQL로 모드 정책·외부 요청 차단·실패·중단·상한·출처 보존·권한·멱등 정산과 migration을 검사한다. 프런트는 상태 머신과 SSR로 데이터 사용 ON/OFF의 저장·요청 매핑과 오류 시 `local/off`, 저장 실패 표시, 세션 교체·늦은 응답·검색 SSE·안전한 출처 표시를 검사한다. 실제 브라우저나 개발 서버를 새로 실행하지 않는다. 이번 검색 조건 보정의 최종 실행 결과는 [개발 현황](../development-status.md#최근-검색-조건-보정)에 기록하고 실제 Tavily 호출·모델 최신성·출처 정확도 평가는 키 등록 후 남긴다.

`0012_network_search` 적용 후 도메인·관측 테이블은 16개다. 기존 실행의 환경 변경은 전체 개발 launcher 또는 개별 API·독립 worker를 종료하고 다시 실행해야 반영된다. 실제 `.env`와 사용자 데이터는 코드 테스트에서 수정하지 않는다.

다운그레이드는 검색 기록이 하나라도 있으면 거부한다. 출처가 없는 임시 DB에서는 검색 테이블·사용자 설정·생성 모드 필드를 제거한다. 실제 답변의 근거를 자동 삭제해 이전 스키마로 맞추지 않는다. 자동 migration 왕복은 격리 테스트 DB에서만 실행한다.
