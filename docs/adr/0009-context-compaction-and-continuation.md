# ADR 0009: 미완성 답변 이어 쓰기와 자동 문맥 압축

- 날짜: 2026-09-09
- 상태: 로컬·허용된 같은 Wi-Fi 환경에 구현, 기능 회귀 검증 완료
- 마이그레이션: `0009_context_compaction` (`0008_deferred_charging` 이후)

## 문제와 결정

완료된 생성만 다음 문맥에 넣으면 사용자가 답변을 중단한 질문에서 알려 준 이름·직업 같은 사실이 빠진다. 출력 상한으로 끝난 부분 답변도 다음 요청에서 온전히 참고할 수 있어야 한다. 또한 전체 원문을 계속 넣으면 모델 문맥 상한에 도달하므로, 원본을 보존하면서 오래된 대화의 핵심 정보를 요약한다.

종료된 생성의 사용자 발언과 실제 답변을 다음 문맥에 포함한다. 오래된 문맥은 같은 단일 생성 worker가 답변 전에 압축하며, 요약 생성 사용량은 사용자가 확정한 정책에 따라 시스템 유지 작업으로 기록하고 사용자 토큰 한도에서 차감하지 않는다. 별도의 모델·개발 서버나 외부 서비스를 추가하지 않는다.

## 미완성 대화와 이어 쓰기

문맥은 같은 작업 공간·대화에 연결된 `completed`, `failed`, `cancelled`, `usage_pending` 생성에서 구성한다. 사용자 발언은 유지하고 실제로 저장된 비어 있지 않은 assistant 본문만 덧붙인다. 빈 placeholder나 화면용 실패 문구를 모델의 답변으로 만들지 않으며, 관계없는 메시지와 다른 작업 공간의 내용을 가져오지 않는다.

모델이 명시한 `finish_reason=stop/length`만 최종 이벤트에 저장한다. `length`이면 화면에 길이 제한과 이어 쓰기 안내를 표시한다. 출력 개수가 설정값과 같다는 이유만으로 잘렸다고 추정하지 않으며, 과거 기록에 종료 사유가 없어도 실제 부분 답변은 문맥으로 사용할 수 있다.

사용자가 `이어서 말해`라고 보내면 최신 요청을 우선하면서 앞의 부분 답변을 자연스럽게 이어 쓰도록 서버 지시를 제공한다. 중단·실패·출력 상한 상태는 참고 정보로 전달하며 원래 질문·답변 내용을 바꾸지 않는다. 이는 새 답변 생성 요청이므로 이전 실행을 재개하지 않고, 같은 요청 키로 중복 실행하지 않는다. 예를 들어 1,024토큰 설정으로 끊긴 뒤 이어 쓰기를 요청해도 새 답변의 출력 상한은 다시 1,024토큰이다.

## 압축 기준과 원문 보존

| 설정                           | 기본값 | 의미                                                  |
| ------------------------------ | ------ | ----------------------------------------------------- |
| `LLM_COMPACTION_TRIGGER_RATIO` | `0.75` | 실제 입력 + 요청 최대 출력이 문맥의 75% 이상이면 압축 |
| `LLM_COMPACTION_TARGET_RATIO`  | `0.55` | 요약과 최근 원문을 구성할 때의 목표 비율              |
| `LLM_COMPACTION_KEEP_TURNS`    | `4`    | 원문으로 우선 유지할 최근 질문·답변 쌍 수             |
| `LLM_COMPACTION_MAX_TOKENS`    | `1024` | 요약 출력 상한; 작은 문맥에서는 문맥 크기의 1/4 이하  |

목표 비율은 시작 비율보다 작아야 한다. 별도 `LLM_MAX_HISTORY_CHARS`를 초과한 경우에도 요약 가능한 오래된 대화를 압축한다. 압축할 과거가 없거나 마지막 질문·답변과 새 질문만으로 모델 한도를 넘으면 원문을 임의로 잘라 보내지 않고 입력·출력 길이를 줄이도록 안내한다.

최근 4쌍을 우선 원문으로 유지하되 길이에 따라 최소 마지막 1쌍까지 줄인다. 서버 정책과 현재 질문은 항상 유지한다. 마지막 미완성 답변도 원문으로 남으므로 이어 쓰기에 필요한 바로 앞의 표현·코드를 모델에 전달한다. 목표 비율을 항상 달성한다고 가정하지 않고, 최종 답변 생성 직전 실제 tokenizer로 입력 토큰을 다시 계산하고 모델 상한·사용자 허용량을 검사한다.

요약 대상은 보존할 최근 원문 앞의 연속 범위다. 한 번에 모델 한도에 넣을 수 없으면 들어가는 오래된 범위부터 배치로 요약하고, 이전 요약과 다음 배치를 합쳐 새 요약을 만든다. 요약 지시는 이름·직업·선호·결정·중요한 수치·미해결 질문·코드 식별자를 남기고 사용자의 명시적 정정을 반영하도록 한다. 중단된 답변이나 불확실한 내용을 확정 사실로 바꾸지 않도록 한다.

요약 입력은 과거 기록이라는 구분을 붙인 JSON 자료로 전달한다. 답변용 문맥에서도 요약은 신뢰하지 않는 과거 참고 정보로 표시하며, 요약 안의 명령이 서버 정책이나 현재 사용자 요청을 대체하지 못하도록 지시한다. 요약은 모델이 만드는 압축 정보이므로 모든 표현·세부 사실의 완전한 보존을 보장하지 않으며 실제 한국어 장기 대화의 회상 품질 평가는 후속으로 수행한다.

## 저장·실행·중단

`conversation_compactions`에 작업 공간·대화·생성 작업 참조, 모델, `prompt_version`, `through_sequence`, 상태·오류, 성공한 요약과 확인된 입력·출력 사용량을 저장한다. 상태는 `running/completed/failed/cancelled`다. 동일 생성에서 여러 배치를 기록할 수 있다. 기존 메시지와 답변 정산 이력은 삭제하거나 덮어쓰지 않는다.

`completed`는 공백이 아닌 요약 내용·양수 범위·확인된 사용량을 갖춰야 한다. 나머지 상태에는 요약 내용을 저장하지 않는다. 같은 작업 공간·대화·모델·prompt version의 최신 완료 범위만 재사용하며, 다음 요청은 저장된 요약과 `through_sequence` 뒤의 원문으로 구성한다. 이는 전체 이전 범위를 대표하는 rolling checkpoint다. 메시지 편집·분기는 아직 제공하지 않으며 도입 시 source hash와 영향받은 요약 무효화 규칙을 추가해야 한다.

생성 승인 시 대화 버전을 재확인하고 `GenerationRun.context_compaction_needed`를 기록한다. 단일 worker가 압축을 처리하며 모델 응답을 기다리는 동안 DB transaction이나 pool 연결을 점유하지 않는다. 같은 대화의 active 작업 제한을 유지하고 요약 저장·답변 준비 전에 실행 상태·중단 요청·접근 권한을 다시 확인한다.

화면은 `이전 대화를 정리 중…`을 표시하며 기존 중단 버튼을 사용할 수 있다. 중단은 요약 연결을 닫고 해당 답변 요청을 종료한다. 완성되지 않은 요약은 사용하지 않는다. 비어 있는 응답, 사용량 미확인, 실패, 명시적 `finish_reason=length`도 유효한 요약으로 채택하지 않고 요청을 실패 처리한다. 앞선 배치에서 이미 완성된 checkpoint는 남아 있어 다음 요청에 사용할 수 있다. worker 재시작 시 남은 `running` 압축 기록은 실패로 정리한다.

## 사용량과 사용자 예산

요약 생성은 시스템 유지 작업이므로 일반 사용자와 시스템 계정 모두 사용자 답변 정산과 분리한다. 확인된 입력·출력 토큰은 `conversation_compactions`에 `provider` 또는 `received` 근거와 함께 기록한다. 확인하지 못한 사용량은 NULL로 두며 0으로 추정하지 않는다. 입력·출력·근거는 모두 함께 저장하거나 모두 NULL이어야 한다.

요약 도중 중단·실패하여 실제 답변을 시작하지 않았다면 사용자 차감은 없다. 요약을 마치고 실제 답변을 생성했다면 그 답변에 제공한 입력(요약문·최근 원문·현재 질문 포함)과 출력만 [ADR 0008](0008-deferred-charging-and-chat-scroll.md)의 완료·중단 후 정산 정책을 적용한다. 같은 원문을 요약하느라 사용한 입력·출력을 사용자에게 한 번 더 청구하지 않는다.

## 호환성과 검증

`0009_context_compaction`은 기존 생성 작업에 기본값 `false`인 압축 대기 표시를 추가하고 요약 테이블을 만든다. 기존 사용자·메시지·무료 예산·정산 수치는 변경하지 않는다. 개발 DB에 해당 head를 적용했으며 도메인 테이블은 13개다.

다운그레이드는 요약과 시스템 유지 사용량 기록·압축 대기 표시를 제거한다. 원본 메시지와 답변 정산은 보존되지만 압축된 문맥을 재사용할 수 없으므로 실행 중인 작업을 종료하고 필요한 기록을 보존한 뒤 호환 코드와 함께 되돌린다. 마이그레이션 왕복과 스키마 drift 검사는 격리된 테스트 PostgreSQL에서 수행한다.

회귀 검증 대상은 중단된 사용자 사실·부분 답변 유지, 명시적 종료 사유, 요약 범위 재사용, 실제 토큰 상한, 원문 보존, 요약 중 중단·실패·재시작, 권한 경계와 사용자 무차감이다. 기능 구현 시 격리 PostgreSQL의 migration 왕복·drift를 포함한 백엔드 329개 테스트(130.83초), 프런트 56개, 빌드·TypeScript·oxlint·Ruff 검사를 통과했다. 이후 화면을 열지 않는 오류 회귀 검사의 추가 사례와 실행별 결과는 [TODO](../../todo.md)에 기록한다.

기능 구현 시 별도로 수행한 실제 MLX 합성 대화는 입력 298·출력 23토큰으로 이름·직업·언어 선호를 요약했고, 요약만 사용한 질문에서 이름·직업을 다시 답했다. 이는 짧은 합성 사례이며 코드 회귀 검사와 구분한다. 100턴 이상 장기 회상 품질을 보장하지 않는다.

실제 모델에서 한 글자 부분 답변 뒤 이름과 직업을 물으면 이름만 답하는 사례도 확인했다. 같은 문맥을 중단 없이 독립 재전송해도 출력 5토큰·확인 수신 4토큰·실제 EOS로 끝나므로 이 관측을 중단 신호 잔류나 원문 전달 누락으로 해석하지 않는다. 다음 평가에는 아주 짧은 중단 본문, 복수 사실 질문, 긴 코드 이어 쓰기를 포함한다. 관련 검증 기록은 [TODO](../../todo.md)에 보존한다.
