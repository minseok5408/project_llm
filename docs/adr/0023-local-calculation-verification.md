# ADR 0023: 로컬 산술 검산과 제한된 Python 출력 추적

- 상태: 채택
- 날짜: 2026-09-22

## 배경

합성 답변 평가에서 일반 모드의 할인 계산과 Python 출력 추론에 오답이 확인되었다. 답변 형식이나 언어를 지켰다는 사실과 계산 결과의 정확성은 별도로 검증해야 한다. 질문의 정답을 프롬프트에 넣거나 일반 모드를 자동으로 깊이 생각하기로 바꾸지 않고, 서버가 제한된 계산 근거를 제공하도록 한다.

## 결정

`backend/app/tools/calculation/`에 질문별 필요성 판단·산술식 계획, 제한된 AST 해석, 생성 단계 연결을 분리한다. 기존 독립 worker에서 웹검색·개인 기억·원문·첨부 문맥을 준비한 뒤, 질문 도구를 연결하기 전에 계산을 준비한다. 기존 문맥 준비가 먼저 단계 한도를 사용한다. 새 서버·모델 프로세스·외부 서비스·환경변수·DB migration은 추가하지 않는다.

현재 질문에 숫자 계산 또는 Python 출력 확인 의도가 있을 때만 동작한다. 번역·코드 인용·설명만 요청하는 경우는 생략한다. 판단은 제한된 규칙이며 모든 자연어 질문의 의도를 판별하지는 못한다. 계획에 전달하는 자료는 현재 질문뿐이다. 과거 대화·개인 기억·첨부·검색 결과를 계산 계획 입력으로 전달하지 않는다.

자연어 계산에는 같은 로컬 모델의 도구 호출을 한 번 사용한다. 계획은 생각하기 OFF·최대 출력 256토큰이며 `calculate`, `trace_python`, `skip_calculation` 중 완성된 호출 하나만 허용한다. 계획 대기는 90초와 기존 모델 요청 시간 상한 중 작은 값으로 제한하고 자동 재시도하지 않는다. Python 출력 질문에서 원문 코드의 경계를 확인할 수 있으면 모델 계획을 생략하고 원문을 직접 추적한다. 최종 답변의 `thinking` 선택과 출력 요청은 기존 사용자 설정을 유지한다.

## 계산과 원문 검증 범위

`evaluate_expression()`은 숫자·괄호·단항 부호·사칙연산·`//`·`%`·제한된 정수 지수의 식을 Decimal로 계산한다. 순환 소수나 정밀도·범위를 넘는 값은 임의로 반올림해 확정하지 않고 `CalculationError`로 거부한다. 음수의 정수 나눗셈과 나머지는 Python의 내림·제수 부호 규칙을 따른다.

순수 계산 API는 상수식을 계산할 수 있지만, 질문에 답하기 위한 `calculate` 경계에서는 상수만 있는 식을 거부한다. 식에 실제 연산이 있어야 하며 서로 다른 질문 수치 두 개 이상과의 연결을 확인한다. 원문의 수치, 명시된 백분율의 변환, 지원하는 단위 환산과 그 보조 상수만 허용해 추측한 최종 숫자를 검산 결과로 포장하는 경로를 제한한다. 이 검사는 숫자의 출처를 제한하며 자연어 조건·연산 순서·대상 선택이 모두 옳다는 보증은 아니다.

`trace_python()`은 Python 프로세스나 `eval`·`exec`·`compile`을 실행하지 않고 허용된 AST만 직접 해석한다. 지원 범위는 숫자·문자열·논리값·리스트·튜플, 단일 이름 대입, `print`·`sum`·`list`·`range`·`len`·`sorted(reverse=...)`, 단일 인자 `map(lambda ...)`, 단일 `for`와 필터를 가진 리스트 컴프리헨션·생성기, 비교·단락 평가·산술·인덱스·슬라이스다. 부동소수는 Python의 의미를 유지하며, 생성기와 `map`의 지연 평가·단회 소비·변수 참조도 보존한다.

추적 대상은 질문의 한 코드 블록 또는 명시적인 질문 줄 뒤에 있는 완전한 코드 원문과 일치해야 한다. 파싱되지 않는 선행 줄을 버리거나 일부 `print` 줄만 선택하지 않는다. 여러 코드 블록, 모호한 경계, 지원하지 않는 구문은 거부한다. import·속성 접근·파일·네트워크·임의 함수 호출·함수/클래스 정의·루프문·서브프로세스는 허용하지 않는다. 이 기능은 일반 Python 실행 환경이나 전체 프로그램 검증기가 아니다.

| 자원                             |                  상한 |
| -------------------------------- | --------------------: |
| 필요성 판단에 사용하는 현재 질문 |              12,000자 |
| 계획의 산술식                    |                 512자 |
| 해석기 입력·추적 원문            |               4,096자 |
| 울타리 없는 추적 원문의 줄 수    |                 128줄 |
| AST 노드 / 깊이                  |            512개 / 32 |
| 연산 횟수                        |               4,096회 |
| 컬렉션·반복 원소                 |                 128개 |
| 문자열 / 표준 출력               |     1,024자 / 4,096자 |
| 숫자 유효 자릿수                 |           최대 80자리 |
| 산술 거듭제곱 지수               |           정수 -16~16 |
| Decimal 내부 지수                | -80~80, 0도 동일 적용 |

값의 크기·중첩과 결과 생성 전 크기도 확인한다. 한도를 넘는 값은 계산을 완료한 것처럼 반환하지 않으며, 오류가 난 코드의 앞부분 출력도 성공 결과로 반환하지 않는다.

## 문맥·실패·사용량

최종 답변에는 실제 식 또는 원문과 계산 결과를 비신뢰 JSON 자료로 넣는다. `verified=true`는 그 식의 연산 또는 제한된 원문 추적 결과를 확인했다는 뜻이며 질문의 자연어 조건 전체를 검증했다는 뜻은 아니다. 모델은 식이 질문 조건에 맞는지 별도로 확인하고, 확인된 결과를 다시 암산해 바꾸지 않도록 지시받는다. 입력·출력 언어와 요청한 형식은 유지한다.

검증된 Python 원문 AST에 `//`가 있으면 정수 나눗셈은 음의 무한대 방향으로 내린다는 의미 정보도 함께 제공한다. 출력이 맞아도 일반 규칙을 잘못 설명한 추가 평가 사례를 보완하기 위한 것이다. 질문별 정답을 하드코딩하지 않으며, 문자열 속 `//`·다른 코드·일반 산술에는 이 정보를 넣지 않는다. 실수 피연산자의 부동소수 정밀도 영향은 별도로 구분한다.

미지원·불명확한 입력·계획 실패·시간 초과·준비 단계 한도 부족은 확인하지 못한 상태를 담은 `verified=false` 문맥으로 전달한다. 모델 공급자가 도구 호출을 지원하지 않으면 자연어 계산 계획을 생략한다. 자료를 추가한 실제 토큰 수를 다시 계산하고 기존 허용량에 맞춰 최종 출력 상한을 줄인다. 문맥 자체가 한도에 들어오지 않으면 답변 생성을 시작하지 않는다.

계획·로컬 도구·답변은 기존 `generation_steps`와 전체 단계 상한을 사용한다. 직접 Python 추적은 계획 호출을 생략하므로 도구와 답변 자리만 필요하다. 시작·문맥 저장·최종 답변 시작 때 기존 대화 접근권한·생성 상태·취소·기억/문서 의존성을 다시 확인한다. 취소는 성공 문맥으로 전환하지 않고 기존 종료 경로로 전달한다.

일반 사용자는 생성 전에 토큰을 예약·차감하지 않는다. 산술 계획과 최종 답변에서 확인된 실제 모델 입력·출력 사용량을 종료·중단 때 합산해 한 번 정산한다. 계획 뒤 답변 시작 전 취소·장애가 발생해도 이미 확인한 계획 사용량은 보존한다. 사용량 자체가 누락·모순된 계획은 확정 사용량으로 청구하지 않으며, 사용량은 정상이지만 도구 인자가 틀린 호출의 실제 사용량은 유지한다. 미확인 호출은 기존 내부 실행 예산 정책을 따라 같은 요청의 반복 우회를 막는다. 로컬 해석 연산을 모델 토큰으로 환산하지 않는다.

시스템 계정의 서비스 예산 면제와 사용량 기록, 자동 압축의 별도 유지 작업·사용자 비차감은 유지한다. 계산 자료는 현재 실행 문맥에만 두고 사용자 원문·개인 기억을 수정하지 않는다. 내부 단계 상태와 사용량은 기존 기록을 사용하며 프롬프트·도구 인자·코드 원문을 SSE 단계 메타에 복제하지 않는다. 별도 처리 과정 목록이나 작업·문맥 드롭다운도 추가하지 않는다.

## 평가와 운영

`scripts/evaluate_answers.py run`은 기본으로 같은 계산 판단·원문 검증·해석·참고 자료 지침을 사용한다. `--no-local-calculation`은 비교용으로 해당 준비를 끈다. 어느 모드인지 보고서의 `configuration.local_calculation`에 남기고, 계획의 입력·호출·실제 사용량은 최종 답변과 분리해서 기록한다. 코드 직접 추적에는 계획 모델 사용량이 없다. 기본 검증 명령은 계속 모델·DB·외부 검색을 호출하지 않는다.

독립 평가는 이미 실행 중인 loopback 모델 서버와 합성 자료만 사용하며 서비스 계정 정산 장부를 변경하지 않는다. 생성 성공이나 도구 성공을 의미 품질 통과로 간주하지 않고 기존 고정 기준으로 답변을 채점한다. 기존 실패 기록·평가셋·채점 기준을 보존하며 추가 산술·코드 사례는 별도 검증으로 다룬다. AI 예비 판독과 사람의 최종 검토를 구분하고, 실제 평가 수치와 채택 여부는 [평가 안내](../answer-quality-evaluation.md) 및 실행별 보고서에 기록한다.

코드 검사는 다음 명령을 사용한다. PostgreSQL 검사는 별도의 격리 DB 설정이 필요하다.

```bash
.venv/bin/python -m pytest backend/tests/test_local_calculation_evaluator.py backend/tests/test_local_calculation.py backend/tests/test_quality_calculation.py
```

답변 생성에 준비 호출과 참고 문맥이 추가되는 만큼 지연·사용량이 늘 수 있다. 식의 자연어 해석, 미지원 코드, 최종 설명의 표현 정확성, 장문·동시 요청의 품질은 제한 해석기만으로 보장하지 않는다. 일반 모드와 깊이 생각하기 모드의 측정도 구분한다. DB schema·환경 파일 변경은 없으며 실행 중인 API·독립 worker에는 사용자가 정상 재시작할 때 코드가 반영된다. 로컬/LAN·loopback·외부 배포 금지 정책을 유지한다.
