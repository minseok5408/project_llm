# ADR 0008: 답변 종료 후 차감과 사용자 스크롤 우선

- 날짜: 2026-09-09
- 상태: 로컬·허용된 같은 Wi-Fi 환경에 적용
- 마이그레이션: `0008_deferred_charging`

## 토큰 차감 시점

새 생성 요청은 토큰을 미리 차감하거나 예산에서 예약하지 않는다. 대기·생성 중에는 사용량과 잔여량이 그대로 유지된다. 답변을 완료하거나 사용자가 중단했을 때 확인된 사용량을 한 번만 차감한다. 기존 ADR 0003·0006의 생성 전 최대 사용량 예약 정책을 이 결정으로 대체한다.

입력 토큰 계산은 모델 문맥 한도와 일반 사용자의 허용량 검사를 위해 유지한다. 현재 예산에서 입력량을 뺀 잔여량보다 최대 출력 설정이 크면 출력 상한을 자동으로 줄인다. 입력과 최소 1개 출력 토큰을 감당할 수 없으면 생성하지 않고 `402`로 응답한다. 시스템 계정은 서비스 토큰 한도를 면제하되 모델 문맥·동시성 제한은 유지한다.

기존 회계 테이블과 이력을 보존하기 위해 `token_reservations.charge_mode`를 추가한다. 기존 행은 `reserved`, 새 생성 요청은 `deferred`다. `deferred` 행의 기존 `reserved_tokens` 열에는 **허용 사용량 상한**만 기록하며 `token_budgets.reserved_tokens`는 증가시키지 않는다. 상태값 `reserved`도 기존 계약과의 호환을 위한 미정산 상태 이름이다. 화면에는 예약량을 표시하지 않는다.

정상 완료는 모델의 최종 입력·출력 사용량으로 차감한다. 중단 시에는 [ADR 0006](0006-persistent-chat-and-usage.md)의 확인 수신량 정책을 따른다. 확인된 출력이 있으면 입력+확인 출력을 차감하고, 확인된 출력이 없으면 0토큰이다. 중단한 생성은 종료 상태이며 같은 요청 키를 다시 보내거나 SSE에 재연결해도 모델을 재개하지 않는다. 새로운 질문은 별도 작업으로 실행한다.

[ADR 0009](0009-context-compaction-and-continuation.md)의 자동 요약은 시스템 유지 작업으로 처리한다. 요약 생성의 입력·출력은 `conversation_compactions`에 별도 기록하며 사용자 한도에서 차감하지 않는다. 요약 이후 실제 답변을 생성했다면 그 답변에 포함된 요약문도 입력 사용량에 포함해 기존 후정산 규칙을 적용한다. `이어서 말해`도 별도 답변 요청이며 설정한 출력 상한과 같은 정산 정책을 적용한다.

## 한도·동시성·장애

사용자 행을 잠근 상태에서 예산과 허용량을 결정하고 미정산 기록을 만든다. 사용자별 미정산 `deferred` 기록은 하나만 허용한다. 서비스의 검사와 DB 부분 고유 인덱스로 다른 작업 공간·동시 요청에서도 미정산 사용량이 중복되지 않게 한다. 기존 예약 방식의 새 요청도 미정산 `deferred` 기록이 있으면 거부한다.

정산은 생성 승인 때 선택한 원래 기간 예산의 사용량에 더한다. 월 갱신·플랜 변경으로 다른 예산에 중복 부과하지 않는다. 동일 정산의 재시도는 같은 입력·출력·산정 기준을 확인하고 기존 결과를 반환한다. 대기 중 중단이나 실행 전 실패에는 차감이 없다.

통신 장애·서버 재시작으로 최종 사용량을 확인할 수 없는 후정산 요청은 `failed`로 종료하고 청구량 0의 `released`/`waived`로 처리한다. 실제 출력량을 0으로 추정한 것이 아니므로 메시지의 미확정 `token_count`는 NULL로 보존한다. 이렇게 종료된 요청은 다음 질문을 막지 않는다. 이미 받은 유효한 최종 사용량은 오류가 뒤따르더라도 기존대로 정산한다. 기존 `reserved` 방식의 불명 사용량과 예약 이력은 이전 정책을 유지한다.

이전 코드가 남긴 `usage_pending`+미정산 `deferred`는 worker 시작과 해당 사용자의 새 생성 승인 전에 같은 방식으로 복구한다. 기존 대화·오류 코드·원래 생성 종료 시각을 보존하고 복구 이벤트를 추가하며, 반복·동시 복구도 한 번만 처리한다. 진행 중인 작업이나 다른 사용자의 요청을 새 생성 승인 과정에서 임의로 종료하지 않는다.

## 스크롤과 명칭

답변의 아래쪽을 보고 있을 때만 새 글자를 따라간다. 사용자가 위로 이동하면 따라가기를 해제하고 현재 읽는 위치를 유지한다. 다시 아래쪽으로 내려오거나 최신 답변 이동 버튼을 누르면 따라가기를 재개한다. 이전 메시지를 추가로 불러올 때는 기존 메시지의 화면 위치를 보존한다.

화면의 생성 제어 명칭은 **중단**이다. 모델 연결을 종료하고 생성·타이핑 대기열을 끝내며 일시정지·재개 기능은 제공하지 않는다. 중단 후 다음 질문은 바로 작성할 수 있고 서버의 종료 확인 뒤 전송할 수 있다.

## 호환성과 검증

업그레이드는 기존 사용량·예약량과 정산 기준을 변경하지 않는다. 미정산 `deferred`가 남아 있으면 이전 코드가 이를 실제 예약으로 오해할 수 있으므로 다운그레이드를 거부한다. 완료된 기록은 수치를 유지한 채 이전 스키마로 내릴 수 있으나 차감 방식 구분 열은 사라진다.

격리 PostgreSQL에서 사전 무차감·한도 자동 축소·최종 차감·중단·진행 중 중복 요청 차단·실패 후 재시도·이전 미정산 복구·멱등성·기간 전환·마이그레이션을 검증한다. 프런트는 사용자의 스크롤 의도, 이전 메시지 위치 보존, 타이핑 중 높이 변화와 중단 상태를 검사한다.
