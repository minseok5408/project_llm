# ADR 0021: 대화 관리·코드 표시·답변 버전과 검색 위치 이동

- 날짜: 2026-09-12
- 상태: 사용자 승인 1~6 구현, 최종 검증 결과는 개발 현황 참조
- 범위: 채팅 UI와 검색·메시지 조회 API 확장. DB migration·환경 설정 변경 없음

## 배경과 결정

대화가 길어지고 재생성·검색·파일을 함께 사용하면서 대화 관리 대상, 모바일 초점, 긴 입력과 코드, 같은 질문의 답변 버전과 검색 위치를 더 명확하게 다룰 필요가 생겼다. 사용자가 승인한 여섯 항목을 기존 생성·권한·정산 정책과 원문 이력을 유지하며 구현한다.

| 항목            | 현재 동작                                                                                             |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| 대화 관리       | 각 행의 메뉴에서 제목 변경·고정·보관/복원·삭제. 제목 입력·삭제 확인은 열린 대화와 별도의 대상 ID 사용 |
| 모바일 사이드바 | Base UI Dialog로 모달·배경 조작·초점을 관리하고 닫을 때 시작점으로 복귀                               |
| 긴 메시지·입력  | 600자 또는 8줄을 넘는 사용자 메시지 접기/펼치기, 입력 요소를 유지한 확대/축소                         |
| 코드 표시       | 언어 표시·원문 복사·기본 가로 스크롤에 구문 색상과 줄바꿈 토글 추가                                   |
| 답변 버전       | 같은 질문의 인접한 답변을 이전/다음 버튼·번호로 탐색하고 현재 답변 이력은 보존                        |
| 검색 위치       | 최신 일치 메시지의 원문 발췌·검색어 강조, 선택한 메시지와 답변 버전으로 이동·앞뒤 페이지 읽기         |

## 대화 관리와 입력 수명

`conversation-row-actions.tsx`는 행 메뉴, `conversation-management-dialog.tsx`는 제목 입력과 삭제 확인을 맡는다. 비동기 관리 요청의 대상 ID는 현재 선택한 대화와 독립적으로 유지한다. 생성 중인 대화의 보관·삭제 제한과 작성자·작업 공간 역할 검사는 기존 서버 정책을 따른다.

`conversation-sidebar-surface.tsx`와 `sidebar-focus.ts`가 데스크톱·모바일 표면과 초점 복귀를 담당한다. 모바일 모달은 배경 조작과 초점 이동을 제한하며 키보드·터치로 열고 닫을 수 있다. 확인창·검색 등으로 이어지는 초점을 관리한다.

`user-message-text.tsx`는 긴 원문의 화면 높이만 접고 `aria-expanded`·`aria-controls`로 상태를 전달한다. 원문을 자르거나 저장 내용을 바꾸지 않으며 검색으로 지정한 메시지는 펼친다. `composer-expansion.tsx`는 같은 textarea를 유지해 초안·커서·한글 IME 조합을 보존한다. 생성 중 입력 가능·전송 차단 정책은 유지한다.

## 코드 색상과 줄바꿈

검증된 [lowlight](https://github.com/wooorm/lowlight) 3.3.0과 highlight.js 11.11.2를 사용한다. 필요한 18개 문법만 등록하고 JS/TS/Python/쉘/HTML 등의 별칭을 명시적으로 정규화한다. 언어를 자동 추측하지 않는다. 패키지는 로컬에서 제공하고 외부 CDN에 코드나 요청을 보내지 않는다.

`code-block.tsx`는 언어·복사·줄바꿈·안전한 React 표시를, `code-highlight.ts`는 지연 로딩·입력 상한·비동기 수명을, `code-highlight-engine.ts`는 문법 분석을 담당한다. `code-block.css`는 밝은/어두운 테마의 토큰 색상을 제공한다. 이번 프로덕션 빌드의 동적 코드 청크 gzip 크기는 약 28KB이며 버전과 빌드에 따라 달라질 수 있는 측정값이다.

SSR은 평문을 즉시 출력한다. 브라우저에서는 내용이 150ms 동안 바뀌지 않을 때만 하이라이터를 불러오고 최대 20,000자·500줄 안의 지원 언어를 분석한다. 새 스트리밍 조각은 분석을 기다리지 않고 원문으로 표시하며 이전 요청·닫힌 화면의 결과는 버린다. AST는 최대 8,000개 노드·40단계 중첩으로 제한하고 text·span만 React로 렌더링한다. HTML 문자열을 삽입하지 않으며 변환 전후 원문 일치도 확인한다.

미지원 언어·상한 초과·로딩/분석 실패는 전체 원문을 평문으로 유지한다. 기본은 가로 스크롤이고 줄바꿈 버튼의 `aria-pressed`는 해당 코드 블록의 표시 상태만 바꾼다. 복사는 언제나 원래 공백·줄바꿈·코드 그대로 전달한다.

## 답변 버전과 원문 보존

생성 정보가 있는 assistant 메시지 조회 결과에 `user_message_id`를 추가한다. `message-versions.ts`는 같은 대화·같은 질문의 인접한 답변만 묶고 `message-version-group.tsx`는 이전/다음 버튼과 현재 번호·전체 개수를 표시한다. 기존 메타데이터가 없는 경우에만 연속 순번·이전 버전 표시를 보수적으로 사용한다.

새 생성과 검색으로 명시한 버전을 표시하면서 토큰 갱신마다 사용자의 탐색 선택을 되돌리지 않는다. 이전 페이지가 붙어도 가능한 한 같은 그룹·선택을 유지한다. 화면에서 이전 버전을 보는 것은 DB의 `is_current`·원문·현재 답변·다음 모델 문맥을 바꾸지 않는다. 선택한 버전의 복사·출처를 표시하고 기존 재생성 가능 여부를 따른다.

## 검색 발췌와 주변 메시지 API

`GET /api/v1/conversations?q=...`의 검색어는 앞뒤 공백을 제외한 최대 200자다. 비어 있지 않은 검색에는 대화별 `search_match`를 추가한다. 본문 일치는 `{message_id, sequence, role, snippet}`이며 해당 대화에서 가장 최근 순번의 일치 메시지를 가리킨다. 원문 발췌 최대 280자와 양끝 생략 기호를 포함해 최대 282자다. 제목만 일치하면 null, 빈 검색어·검색어 생략은 기존 목록 응답을 유지한다. `%`·`_`도 리터럴이며 발췌·강조에 HTML을 실행하지 않는다.

| 메시지 조회 조건        | 의미                                  |
| ----------------------- | ------------------------------------- |
| 방향 생략               | 기존처럼 최신 메시지 페이지           |
| `before=<sequence>`     | 그 순번보다 오래된 메시지             |
| `after=<sequence>`      | 그 순번 이후 메시지                   |
| `around=<message UUID>` | 표적을 포함한 앞뒤의 제한된 메시지 창 |

`before`·`after`·`around` 중 둘 이상을 지정하면 `422`다. `limit`은 기본 50, 범위 1~100이며 `around`의 개수는 앞뒤를 합친 상한이다. 대화 시작·끝에서는 더 적게 반환할 수 있다. `items`는 모두 시간순이고 `next_cursor`는 다음 `before`, `newer_cursor`는 다음 `after`의 순번이며 해당 방향에 더 없으면 null이다.

검색은 기존 작업 공간·사용자 소속·대화 삭제 경계를 유지한다. 다른 대화·계정·삭제된 대화의 메시지나 존재하지 않는 UUID를 `around`로 지정하면 `404`이며 응답은 `no-store`다. 개인 기억이나 권한 밖 원문을 검색 발췌로 섞지 않는다.

`conversation-search-result.tsx`가 원문 발췌·검색어 강조와 대화/메시지 ID를 전달한다. 대화 세션은 표적 주변 최대 50개를 조회하고 앞뒤 커서로 이어 읽는다. `use-chat-scroll.ts`는 표적 위치를 찾고 장문·이전 답변 버전을 펼치도록 연결한다. 기존 초안·진행 SSE·계정 전환 시 늦은 응답 차단을 보존한다.

## 검증과 적용

검증 범위는 대화 관리 대상·비동기 오류, 모바일 초점, 원문·IME·접기/확대, 코드 언어/상한/이스케이프/복사/취소, 답변 그룹·버전 선택, 검색 발췌·권한·양방향 커서·중복 없는 원문 이동이다. 프런트와 검색·대화·저장소 관련 PostgreSQL 검사를 통과했으며 전체 백엔드 재실행을 뜻하지 않는다. 검사 수와 최종 결과는 개발 현황에 모아 기록한다. TypeScript·lint·프로덕션 빌드도 통과했다. 최종 포맷·Headless Chrome 합성 화면 확인 결과는 [개발 현황의 최근 채팅 UI 개선](../development-status.md#최근-채팅-ui-개선)에 기록한다.

새 개발 서버를 실행하거나 실제 계정을 변경·실제 모델을 추론하지 않는다. DB migration·환경 설정 변경은 없으며 head `0017_schema_roles`와 도메인·관측 21개 테이블을 유지한다. 이전 ADR과 날짜별 검사 결과는 당시 이력으로 보존한다.
