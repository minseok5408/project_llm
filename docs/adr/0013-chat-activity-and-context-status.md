## 대화별 상태와 전역 작업

완료 점은 다른 대화에서 종료된 작업에만 표시한다. 현재 보고 있는 대화의 종료는 즉시 읽은 상태로 처리하고, 대화 선택 시 해당 대화의 모든 알림을 조회 완료 전에 지운다. 생성 ID별 종료 처리 기록은 유지해 늦은 이벤트로 점이 다시 생기지 않게 한다.

`ChatStore`는 로그인한 계정 세션에 속한 대화들을 관리하고, `ConversationSession`은 대화 하나의 초안·메시지·요청 재시도 키·생성 SSE 연결을 소유한다. 대화를 이동해도 이전 연결을 종료하지 않는다. 늦게 도착한 접수·취소·생성 응답은 원래 대화에만 반영하며 현재 선택한 대화나 주소를 바꾸지 않는다. 새 대화의 초안은 작업 공간마다 구분한다.

상단 작업 메뉴와 다른 대화 작업 안내에서 진행·대기·검색·압축·중단 확인·연결 오류를 확인한다. 다른 대화의 작업도 중단하거나 다시 연결할 수 있다. 완료·실패·중단·사용량 확인 필요 알림은 생성 ID마다 한 번만 만들며 최대 10개를 보관한다. 알림의 대화로 이동하거나 개별적으로 닫을 수 있다. 현재 창에서 관측한 종료를 알리며 브라우저 시스템 알림은 사용하지 않는다.

`GET /api/v1/generations/active`는 인증된 사용자 본인의 진행 작업만 반환하며 현재 작업 공간 소속을 다시 검사한다. 초기 연결과 창 포커스 복귀 때 이 API를 사용하므로 대화 목록의 페이지나 필터에 없는 작업도 복원한다. 이미 연결한 작업은 중복 연결하지 않는다. 소속 사용자의 공유 대화에서 직접 연결한 생성도 기존 대화 권한을 적용한다.

계정당 진행 생성 1개, DB당 단일 실행자와 기존 서버 권한·정산 정책을 유지한다. 다른 대화의 생성 중에는 새 질문을 작성할 수 있고 전송은 완료 또는 중단 후에 허용한다. 서버가 최종 동시성을 검사한다.

초안·알림·화면 캐시는 계정 세션의 메모리에만 둔다. 새로고침하면 초안과 알림은 초기화되지만 서버에 저장된 대화·진행 생성·문맥 측정값은 다시 읽는다. 로그아웃·세션 만료·계정 전환 때 모든 대화 연결과 메모리를 정리한다. 이전 계정의 늦은 응답은 새 상태에 반영하지 않는다. 사용량과 메시지의 겹치는 재조회는 이전 응답이 최신 값을 되돌리지 않도록 처리한다.

## 문맥 측정과 표시

기존 `generation_events`의 `meta.context`에 요청별 측정값을 기록한다. 별도 테이블이나 마이그레이션은 추가하지 않는다. 공개 정보는 생성 ID·준비 상태·입력 토큰·확인된 출력 토큰·최대 출력·문맥 상한·이번 입력에 사용한 요약의 마지막 메시지 순번·압축 상태다. 원문이나 요약 내용은 이 정보에 넣지 않는다.

- 승인 시에는 준비 상태를 기록한다. 압축이 필요한 요청의 최소 승인 입력은 최종 문맥을 대표하지 않으므로 입력량과 요약 반영 범위를 `null`로 둔다.
- 압축 시작·완료를 이벤트로 보낸다. 완성된 요약을 사용해 입력을 조립한 후 실제 반영 순번을 기록한다.
- 검색 자료까지 반영한 뒤 답변 생성 직전에 실제 tokenizer 입력량과 실행자의 문맥 상한·출력 한도를 다시 기록한다.
- 종료 시에는 기존 정산 기록의 확인된 `provider`·`received` 출력만 공개한다. 알 수 없는 출력은 `null`로 유지한다. 압축 실패·중단은 성공과 구분한다.
- 생성 조회와 메시지 목록은 마지막 저장 측정값과 압축 시도·정산 기록을 조합해 같은 상태를 제공한다. 과거 요청의 요약 반영 범위를 이후 요약으로 바꾸지 않는다. 새 측정 기록이 없는 과거 생성은 미확인으로 표시한다.

입력창 아래 문맥 메뉴는 최근 요청의 측정값을 보여 준다. 작성 중인 초안은 포함하지 않는다. 출력이 아직 확인되지 않았으면 입력 기준 비율이라고 표시하며, 확인된 출력이 있으면 입력과 출력의 합을 사용한다. 최대 출력은 한도로만 표시하며 사용량에 더하지 않는다. 계정 잔여 토큰은 기존 사용량 설정에서 관리한다. 압축 비용의 사용자 면제와 답변 종료 후 실제 사용량 정산은 변경하지 않는다.

## 검증과 적용

프런트 상태·SSR 검사로 대화 왕복·초안·백그라운드 생성·중단·완료 알림 중복 방지·계정 전환·미확인 문맥·사용량 응답 순서를 확인한다. 격리 PostgreSQL에서는 승인·실행·실패·중단·요약 범위 보존·권한·정산과 새 API를 검사한다. 최종 실행 결과는 [TODO](../../todo.md#priority-development)에 기록한다.

기존 개발 DB와 `.env`는 변경하지 않는다. 웹·API·모델 개발 서버나 원격 미리보기는 실행하지 않는다. 변경은 기존 실행 구성이 다음에 다시 시작될 때 반영되며, 코드 변경을 되돌릴 때 DB 마이그레이션은 필요 없다.
