# ADR 0022: 합성 답변 품질 평가와 사람 채점 기준

- 상태: 채택
- 날짜: 2026-09-22

## 배경

기존 문맥·언어·검색 도구·문서 검색 평가는 범위와 지표가 다르다. 단어 포함 여부나 검색 순위가 높은 결과만으로 실제 답변의 사실성·인용 정확성·사용자 요구 충족을 보장할 수 없다. 새 개발 순서 1번에서 공통 평가 기준을 먼저 정의한다.

## 결정

`backend/evaluation/`에 서비스 데이터와 분리된 합성 24개 사례·67개 원자 기준과 실행·채점·비교를 둔다. 기존 문맥 조합·언어 정책·검색/파일 참고 지침·MLX 공급자를 재사용하고 제품의 판단 정책이나 API를 변경하지 않는다. 기대 언어·정답·채점표는 모델 입력에 넣지 않는다.

기본 명령은 네트워크 없는 자료 검증이다. 실제 추론은 명시적인 `run`에서 기존 loopback 서버만 사용한다. 모델 실행 보고서는 실제 입력·답변·자료·코드 해시, 생성 설정·샘플링·확정/부분 사용량·지연을 남긴다. 모델 프로세스 메모리는 미측정으로 둔다. 개발 DB와 사용자 토큰 장부에는 접근하지 않는다.

사람은 기준별 0~2점과 근거를 기록한다. 전체 보고서·답변에 결합된 채점만 허용하고 미실행·실행 실패·미채점을 품질 통과로 처리하지 않는다. 초기 정책은 전체 0.90, 사례별 0.75, 필수 기준 0점 0건이다. 기준선은 전체 평가·채점을 완료하고 절대 기준을 통과해야 하며, 후보의 허용 하락은 전체 0.02·사례별 0.25다. 수치는 초기 목표이며 달성한 모델 성능이 아니다.

비교는 같은 자료·rubric·사례 정의·반복 횟수를 요구한다. 모델·프롬프트·설정은 비교할 변경 대상이므로 차이를 명시하고 비교할 수 있다. 부분 사례 실행을 전체 기준선으로 사용하거나 저장된 성공 표시만 재사용하지 않는다.

## 범위와 복구

고정 웹·파일 자료는 최종 답변 단계만 평가한다. 검색 필요성 판단·실제 검색·장기 기억/압축·문서 파싱/검색 통합 평가는 새 2~4번에 남긴다. 기존 평가 도구는 유지하며 이전 어휘/검색 순위 결과를 새 의미 점수로 변환하지 않는다. CI와 배포 차단은 새 7번 후속이다.

DB migration·환경변수·UI 변경은 없다. 평가 결과는 기본 예시에서 Git 제외 `data/evaluations/`에 0600으로 저장하며 새 실행이 기존 보고서를 덮어쓰지 않는다. 도구를 되돌려도 서비스 데이터와 실행 정책에 영향이 없다. 절차·해석·종료 코드는 [평가 안내](../answer-quality-evaluation.md)를 따른다.
