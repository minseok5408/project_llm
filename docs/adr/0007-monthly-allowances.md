# ADR 0007: 월 무료 토큰과 플랜별 기간 예산

- 날짜: 2026-09-09
- 상태: 채택
- 마이그레이션: `0006_monthly_allowances`

## 무료 정책

일반 `member`에게 매월 20,000토큰을 자동 지급한다. 한국 시간(`Asia/Seoul`) 매월 1일 00시부터 다음 달 1일 00시까지가 한 기간이며 잔여량은 이월하지 않는다. 월 중 가입해도 그달 전액을 받는다. 입력 1,000 + 답변 1,000토큰씩이면 약 10회를 목표로 한 양이지만 대화 이력·답변 길이·thinking 사용량에 따라 실제 질문 횟수는 달라진다. 다시 전달하는 대화 이력도 매번 입력 토큰에 포함된다.

무료 지급에 시스템 계정의 수동 할당은 필요하지 않다. `system` 계정은 무료 예산을 만들지 않고 기존 한도 면제·실제 사용량 기록을 유지한다. 서비스 역할과 작업 공간 권한은 바꾸지 않는다.

## 플랜과 예산의 구분

`UsagePlan`은 플랜 정책을, `TokenBudget`은 사용자·기간별 발급 당시 한도와 사용·예약 이력을 저장한다. 기본 무료 플랜이 없으면 서비스가 코드 `free-monthly`, 이름 `무료`, 한도 20,000으로 준비한다. 매월 예산은 이 플랜을 참조하는 사본이며 기존 기간의 사용량을 덮어쓰지 않는다.

`0006_monthly_allowances`는 기존 `token_budgets`에 `source`를 추가한다. 도메인 테이블 수는 12개로 유지하며 기존 예산·사용량·예약은 `source=plan`으로 보존한다.

| source | 의미 | 선택 규칙 |
| --- | --- | --- |
| `free_monthly` | 해당 한국 달의 자동 무료 예산 | 유효한 plan 예산이 없을 때 사용 |
| `plan` | 기존 기간 예산 및 향후 결제 등급별 예산 | 유효한 기간 동안 무료보다 우선 |

사용자별·source별로 같은 시각에 유효한 예산은 하나만 허용한다. 서로 다른 source의 기간은 겹칠 수 있지만 한 요청에서 합산하지 않는다. plan이 유효하면 소진돼도 무료분으로 자동 전환하지 않고 부족한 요청을 거부한다. plan 기간이 끝나면 현재 달의 무료 잔여량을 사용한다. 무료 기간에 이미 사용한 양을 다시 채우지는 않는다.

예약에는 선택한 예산을 고정한다. 월 경계나 plan 시작·종료 후 완료되는 작업도 원래 예약의 예산에 정산하며 새 예산으로 사용량을 옮기지 않는다. 미확정 사용량은 기존 정책대로 예약을 유지한다.

## 지급 시점과 멱등성

`MonthlyAllowanceService`가 가입 transaction 안에서 이번 달 무료 예산을 준비한다. `GET /api/v1/usage`와 생성 승인에서도 현재 월의 예산 존재를 확인하므로 기존 회원도 재접속 후 해당 요청을 거치면 적용된다. 유효한 plan이 있으면 이를 반환하고 불필요한 무료 발급은 건너뛴다. 사용자·월을 식별하는 멱등 키와 사용자 잠금으로 동시 요청·재시도에서 중복 발급을 막는다.

별도 cron이나 갱신 서버는 두지 않는다. 한국 시간 월 경계부터 새 기간이 유효하며 실제 행은 그달 무료 예산이 필요한 첫 요청 때 생성한다. 방문하지 않은 과거 달을 소급 적립하지 않는다. 경계 시각은 한국 달력으로 계산하고 DB에는 UTC `timestamptz`로 저장한다.

## 결제 확장과 유지보수

향후 결제 등급도 플랜 정책에서 기간 예산을 발급하는 동일한 구조를 사용한다. 실제 결제사·가격·구독·webhook·환불 처리는 이번에 구현하지 않는다. 검증된 결제 이벤트를 예산 발급과 연결하고 기존 사용 이력을 보존하는 일은 후속이다.

기존 `create-plan`·`grant-budget` CLI는 로컬 유지보수용으로 남긴다. 무료 월 지급의 일반 경로는 이 명령이나 시스템 운영자의 매월 개입에 의존하지 않는다. 공개 관리 화면도 추가하지 않는다.

## 검증과 이전 구조 호환성

검증 범위는 한국 시간 월말·연말 경계, 월 중 가입 전액, 기존 회원 적용, 동시 요청의 단일 발급, 미이월, plan 우선·소진 시 무료 전환 금지, 기간 종료 후 무료 잔여량과 이전 예산 정산이다. 최종 테스트 결과는 [TODO](../../todo.md)의 월 무료 정책 기록에 남긴다.

개발 DB에 업그레이드와 `alembic check`를 적용해 drift가 없음을 확인했다. 다운그레이드는 무료 예산 행이 하나라도 있으면 중단한다. 이전 코드는 같은 기간의 무료·plan 예산을 구분하지 못하기 때문이다. 데이터가 없는 임시 DB에서만 자동 왕복 검증을 수행한다. 실제 데이터를 이전 구조로 옮겨야 하면 예산·예약의 보존과 호환 계획을 먼저 세우며 무료 예산을 자동 삭제·합산하거나 사용량을 초기화하지 않는다.
