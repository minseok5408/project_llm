# ADR 0020: 저장 항목의 역할 정리와 대화·정산 참조 무결성

- 날짜: 2026-09-12
- 상태: 구현·실제 개발 DB 적용·검증 완료
- 코드 migration head: `0017_schema_roles` (`0016_local_file_rag` 다음)
- 범위: 도메인·관측 22개 테이블을 21개로 정리. 외부 API·환경 설정 유지

## 배경

파일은 이미 대화 하나에 속하고 실행 코드는 문서 하나의 처리 버전 하나를 전제로 동작한다. 별도 첨부 연결은 같은 소속을 중복 저장했고, 대화 설정과 메시지 프롬프트 버전은 업무 경로에서 사용하지 않았다. 생성 옵션 JSON에는 별도 출력 상한 열과 같은 값도 들어 있었다. 반대로 예산·정산·압축·출처 필드는 이름이 비슷해도 보존해야 하는 의미가 달랐다.

현재 코드와 실제 저장 값의 사전 점검을 바탕으로 사용하지 않거나 복원 가능한 중복 항목만 정리한다. 서로 다른 대화의 메시지나 다른 사용자의 정산 기록을 연결하는 오류는 애플리케이션 검사에 더해 DB가 거부하도록 한다.

## 테이블별 역할

| 영역             | 테이블                                                     | 책임                                                                        |
| ---------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| 계정·인증        | `users`, `auth_identities`, `auth_sessions`                | 계정 상태·플랫폼 역할, 인증 수단, 만료·철회 가능한 세션                     |
| 공유 범위        | `workspaces`, `workspace_members`                          | 데이터의 작업 공간과 사용자별 소속·역할                                     |
| 사용자 설정·기억 | `user_preferences`, `user_memories`                        | 데이터 사용 정책과 revision, 명시적으로 저장한 기억과 세대                  |
| 대화 원문        | `conversations`, `messages`                                | 목록·대화 모델·순번과 원문·답변 상태·최종 답변 토큰 수                      |
| 예산·정산        | `usage_plans`, `token_budgets`, `token_reservations`       | 플랜 기본값, 부여 당시 예산·사용 누계, 요청별 허용량·확정 정산              |
| 실행·재연결      | `generation_runs`, `generation_events`, `generation_steps` | 멱등 생성 작업·입력 문맥, SSE 재생 기록, 모델·도구별 실행·사용량            |
| 파생 문맥·검색   | `conversation_compactions`, `web_search_runs`              | 재사용 가능한 요약·시스템 유지 사용량, 생성별 검색 상태·채택 출처           |
| 파일             | `documents`, `document_versions`, `chunks`                 | 대화별 활성 파일, 단일 원본의 처리 상태·도구 이력, 검색 본문·벡터·근거 위치 |
| 실행자 관측      | `worker_heartbeats`                                        | 실행자 상태 관측. 실행 권한은 기존 DB advisory lock으로 결정                |

도메인 20개 테이블은 UUID 기본 키를 사용한다. `worker_heartbeats`는 고정 name 키와 UUID 실행자 ID를 사용한다. `alembic_version`은 위 21개에 포함하지 않는다.

## 제거·통합한 항목

- `attachments`를 제거하고 `documents.conversation_id`와 `deleted_at`을 파일 소속·활성 여부의 기준으로 사용한다. 대화 삭제와 문서 삭제 표시·검색 조각 제거는 기존 서비스의 같은 트랜잭션에서 처리한다.
- `document_versions`의 unique를 `(document_id, version)`에서 `document_id`로 좁혀 문서당 최대 하나의 처리 버전을 보장한다. 원본과 문서 ID, 재시도 횟수, 검색 조각 참조는 유지한다. `version` 숫자는 원본 경로·출처 계약에 남긴다.
- `document_versions.media_type` 저장을 제거한다. 업로드 입력의 MIME 검증은 유지하며 PDF는 `application/pdf`, 지원 텍스트 형식은 `text/plain`으로 복원할 수 있는 기존 값만 변환을 허용한다.
- 업무 경로에서 사용하지 않는 `conversations.settings`와 `messages.prompt_version`, 관련 제약·repository 인자·검증을 제거한다. 압축 요약의 `prompt_version`은 재사용 판정에 쓰이므로 유지한다.
- `generation_runs.options` JSON 대신 `thinking` Boolean과 기존 `max_output_tokens`를 사용한다. 승인 때 확정한 상한을 실행과 문맥 계산에서 일관되게 읽는다. 외부 API의 `options.thinking`·`options.max_tokens` 형식과 검증은 유지한다.

## 참조 범위를 DB에서 보장

| 참조                      | 복합 외래 키가 보장하는 조건                                                      |
| ------------------------- | --------------------------------------------------------------------------------- |
| 생성 → 사용자/답변 메시지 | `conversation_id`가 같은 메시지만 `user_message_id`·`assistant_message_id`로 연결 |
| 생성 → 정산 기록          | 생성의 `user_id`와 예약·정산 기록의 `user_id` 일치                                |
| 압축 요약 → 생성          | 압축 요약의 `conversation_id`와 생성의 `conversation_id` 일치                     |

기존 대화→작업 공간, 메시지·압축 요약→대화의 범위 제약과 함께 적용한다. 참조 대상으로 `messages(conversation_id, id)`, `token_reservations(id, user_id)`, `generation_runs(conversation_id, id)`의 unique 세 개를 추가한다. `id`가 이미 유일하더라도 이 조합을 외래 키로 참조하려면 해당 unique가 필요하므로 중복처럼 보인다는 이유로 제거하지 않는다. 소속 변경·접근 허용·메시지 역할·정산 상태 검증은 기존 서비스도 계속 담당한다.

## 보존하는 값의 의미

`users.platform_role`의 `system/member`, `workspace_members.role`의 `owner/admin/member`, `messages.role`의 `user/assistant/system`은 서로 다른 권한·발화 역할이다. 표시 이름이나 이메일·클라이언트 입력으로 시스템 권한을 얻을 수 없다.

플랜의 기본 한도와 예산의 발급 당시 한도는 다르다. `token_budgets`의 한도·사용 누계·기존 예약량과 멱등 부여 정보는 보존한다. `token_reservations.reserved_tokens`는 과거 사전 예약과 현재 후정산 방식의 요청별 허용 상한을 표현하며, `charge_mode`와 함께 해석한다. 현재 일반 사용자는 생성 전에 예약·차감하지 않고 한도만 확인한 뒤 완료·중단 시 확인된 사용량을 한 번 차감한다. 시스템 계정은 서비스 예산을 면제하되 사용량은 기록하고 모델 문맥·동시성 제한은 유지한다.

`messages.token_count`는 최종 답변 단계의 출력량이고 정산에는 검색 판단 등을 포함한 모든 모델 호출의 확정 입력·출력을 합산한다. `generation_steps.budget_tokens`는 사용량을 알 수 없는 실패에서도 실행 상한을 유지해 반복 시도의 예산 우회를 막는다. 따라서 두 값을 정산 합계와 같은 필드로 합치지 않는다.

압축 요약은 모델·프롬프트 버전·원문 범위·완료 상태가 맞을 때만 재사용하고 시스템 유지 사용량을 별도로 기록한다. 압축 사용량은 사용자 한도에서 차감하지 않으며 실제 답변에 사용한 요약 입력은 기존 정산 정책을 따른다. 메시지 모델, 문서의 파서·임베딩 버전·스캐너 기록은 당시 처리 이력을 보존한다. 메시지 원문·생성 입력, 파일 해시·크기·출처 위치, 검색 채택 출처, 기억·문서 세대 의존성도 삭제하지 않는다. 대화·메시지·요약·검색·실행 단계는 상태가 갱신되는 기록이므로 공통 수정 시각을 일괄 제거하지 않는다.

## 데이터 보존과 되돌리기

업그레이드는 관련 테이블을 같은 트랜잭션에서 잠그고 다음 상태가 있으면 거부한다.

- `queued`·`running` 생성
- `{}` 이외의 대화 설정 또는 NULL이 아닌 메시지 프롬프트 버전
- `thinking`·`max_tokens` 외의 생성 옵션, Boolean이 아닌 thinking, 기존 출력 상한과 다른 max_tokens
- 문서 활성 여부와 첨부 연결의 존재 여부가 일치하지 않는 행
- 문서당 여러 처리 버전 또는 확장자로 재구성할 수 없는 MIME 이력

복합 외래 키와 맞지 않는 기존 연결도 제약 적용 때 거부한다. 원문을 지우거나 소속·이력을 추정해 수정하지 않는다. 이런 데이터가 있으면 원래 값을 보존한 상태에서 별도 이전 방안을 먼저 정해야 한다.

다운그레이드는 진행 생성이 없을 때 `thinking`·`max_output_tokens`에서 옵션 JSON, 활성 문서에서 첨부 연결, `{}` 대화 설정·NULL 메시지 버전·확장자별 MIME을 재구성한다. 복합 외래 키는 이전 단일 참조로, 문서 버전 unique는 이전 조합으로 되돌린다. 재구성한 첨부 연결 ID는 새로 발급하고 시각은 문서에서 가져오므로 과거 연결 행의 ID·시각을 그대로 복원하는 절차는 아니다. 문서 ID·원본·검색 조각·대화·정산 데이터는 보존한다. 전체 `downgrade base`는 별도 이전 migration의 데이터 삭제·거부 정책을 따르며 실제 DB 복구 수단으로 임의 실행하지 않는다.

## 검증과 적용 상태

실제 개발 DB에 `0017_schema_roles`를 적용하고 도메인·관측 21개 테이블을 확인했다. 적용 전후 보존 대상 21개 테이블의 모든 행 해시가 일치한다. `data/backups/`의 적용 전 백업을 임시 복제 DB에 복원하고 upgrade→downgrade→upgrade 후 보존 행 해시·스키마 일치도 확인했으며 복제 DB는 삭제했다. 관련 PostgreSQL 검사 108개와 프런트 171개를 통과했다. 최종 전체 검사 결과와 완료 판정은 [개발 현황](../development-status.md#최근-db-역할-정리)에 기록한다.

진행 생성 0건과 적용 직전 실제 앱이 종료된 상태임을 확인했으며 새 서버 실행·프로세스 재시작·`.env` 변경은 하지 않았다. 확정 결과는 [개발 현황](../development-status.md#최근-db-역할-정리), 실행·되돌리기 절차는 [run.md](../../run.md#db-기반-변경-롤백)를 따른다. 이전 ADR과 날짜별 검사 결과는 당시 이력으로 유지한다.
