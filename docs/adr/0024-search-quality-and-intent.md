# ADR 0024: 검색 필요성 판단과 근거 답변 평가

- 상태: 채택
- 날짜: 2026-09-23

## 배경

기존 자동 검색은 최신성 단어가 있으면 검색 준비에 진입했고, 준비 모델에는 이미 검색이 필요하다는 전제를 주었다. 따라서 “오늘 날씨가 좋다”의 번역처럼 주어진 글만 변환하면 되는 요청에서 불필요한 검색이 일어날 수 있었다. 반대로 최신성 단어가 없는 가격·직책·추천이나 “그럼 부산은?” 같은 후속 질문은 검색 후보에서 빠질 수 있었다.

검색 도구 호출·사용량·중단 검사는 실제 질문의 검색 필요성, 검색어의 대상과 조건, 검색 자료의 최신성, 최종 주장과 출처의 일치를 측정하지 않는다. 새 개발 순서 2번은 제품의 검색 진입 판단과 이 의미 품질 평가를 연결한다.

## 결정

`tools/web_search/context.py`의 규칙은 검색을 확정하는 판정이 아니라 로컬 모델 판단에 보낼 후보를 고르는 단계로 사용한다. 명시적 검색 금지와 개인 기억 요청을 제외하고, 인용문·코드 안의 단어를 검색 지시로 해석하지 않는다. 번역·기초 정의·제공 코드 작업을 구분하고 변하는 공개 사실·명시적 검색·최근 공개 문맥의 후속 질문을 후보에 포함한다. 규칙에 잡히지 않는 표현까지 판별하는 보장은 없다.

기본 도구 호출 경로는 현재 질문의 목적을 로컬 모델로 판단한 뒤 아래 결과 중 하나를 선택한다.

| 결과                        | 의미와 처리                                                                                                                                           |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `web_search`                | 사용자 발언에서 확인한 원문 표현으로 검색어를 만든다. 인자·길이·사용량·단계 한도 검증 뒤 외부 도달성을 확인하고 검색한다.                             |
| `finish_search(not_needed)` | 자동 모드에서 외부 사실 확인이 필요하지 않다. 외부 도달성 검사·검색·검색 실패 안내를 생략하고 원래 질문에 답한다. 판단 모델의 실제 사용량은 유지한다. |
| `finish_search(no_query)`   | 검색 대상이 모호하다. 외부에 요청하지 않고 대상을 확인하도록 답변 문맥에 안내한다.                                                                    |
| `finish_search(sufficient)` | 이미 얻은 자료가 대상·시점에 맞는 직접 근거로 충분하다. 검색을 끝내고 자료를 사용한다. 자료가 없는 호출은 거부한다.                                   |

데이터 사용 OFF·요청의 `local/off`·서버에 저장된 로컬 전용 설정은 모델 판단보다 우선한다. 검색 도중 설정 revision이나 접근권한·생성 상태가 바뀌면 기존 중단 경로를 따른다. `web_search=on` 또는 현재 질문에 명시적인 검색 요청이 있으면 `not_needed`로 건너뛰지 못한다. 명시적 검색 금지는 이 경우에도 우선한다.

외부 도달성 확인은 유효한 검색어와 도구 단계가 확보된 뒤에 수행한다. 설정 화면의 초기 상태 조회·사용자의 수동 재확인에서 수행하는 별도 연결 검사는 그대로 유지한다. `WEB_SEARCH_AGENT_ENABLED=false` 또는 도구 호출 미지원 공급자의 기존 단일 검색 호환 경로는 의미 판단을 수행하지 않고 현재 질문 앞부분을 사용한다.

검색 판단 프롬프트는 목적·원문 표현·종료 사유의 규칙을 짧게 전달하며 Qwen의 기본 XML 도구 호출 예시를 명시한다. 직책·가격·구매나 여행 추천은 “최신”이라는 단어가 없어도 외부 검색이 필요하다고 명시한다. `web_search`의 `terms`는 JSON 배열로 전달하고, 서로 떨어진 구절은 하나의 원문처럼 합치지 않고 별도 항목으로 선택한다. 대상·조건을 나타내는 짧은 핵심 구절만 선택하고 “검색해 줘” 같은 지시·인사 표현은 제외하도록 한다. 최신 답을 모르는 것은 `no_query`의 사유가 아니며 실제 공개 대상이 없는 경우와 구분한다. 공식 사이트의 자료여도 과거 목록·예전 날짜·지원 권장 버전만 있으면 최신판을 확인하는 충분한 근거로 판단하지 않는다.

MLX 어댑터의 도구 호출에만 `temperature=0`, `presence_penalty=0`을 적용하여 문장 표현의 다양성을 위한 설정이 도구 인자 선택을 바꾸지 않도록 한다. 일반 답변의 샘플링과 사용자가 선택한 생각하기 설정은 유지한다. `tool_choice=auto`도 유지하여 서버가 입력 토큰 계산 때 없던 강제 도구 지시를 실제 생성에 덧붙이지 않도록 한다. 완성된 도구 호출 한 개와 계산한 입력 토큰 수에 맞는 실제 사용량의 검증을 계속 적용한다.

## 검색어와 근거의 경계

모델 판단에는 현재 질문과 최근 사용자 발언 최대 4개의 제한된 후보를 사용한다. 과거 발언에서 개인 정보·내부 메모로 감지되는 내용을 제외하며, 선택한 과거 표현은 합계 80자를 넘을 수 없다. 검색어의 각 표현은 해당 발언의 연속된 원문과 일치해야 하고 전체 검색어는 기존 길이 상한을 따른다. 생략된 후속 질문에는 필요한 공개 대상과 앞 질문의 주제를 함께 선택하며, 대상을 여러 개로 해석할 수 있으면 추측하지 않는다. 이 처리는 원본 메시지·압축 요약·기억을 수정하지 않는다. 전체 대화·압축 요약·개인 기억·첨부 원본을 검색 공급자에 보내지 않는다.

검색 결과는 공급자의 제목·요약·URL이며 웹페이지 본문을 읽은 자료로 표시하지 않는다. 판단과 최종 답변 지침 모두 자료 속 명령을 비신뢰 데이터로 취급한다. `retrieved_at`은 조회 시각이며 발표일·사건일·최신성의 증명이 아니다. 대상·기간·지역과 자료 속 날짜를 확인하고, 오래되거나 날짜가 없거나 상충하는 근거만 있으면 최신 사실을 확정하지 않도록 한다. 각 주장은 직접 뒷받침하는 출처 번호와 연결하며 제공하지 않은 본문·출처를 만들지 않는다.

검색 참고 지침의 앞부분에서 인물·버전·가격 같은 변하는 사실은 제공된 자료의 직접 근거 범위에서만 답하도록 한다. 학습 지식의 인물·수치·현재 상태로 자료의 답을 대체하거나 보충하지 않는다. 자료가 합성·가상임을 명시하면 그 한계를 유지하고 현실의 최신 사실은 확인되지 않았다고 밝히며, 확인 불가 안내 뒤에 추측한 현실의 답을 덧붙이지 않는다.

`build_grounded_search_messages()`는 검색 자료와 메시지를 복사하고 기존 system 참고 문맥 위치에 자료를 유지하면서 마지막 사용자 메시지의 답변용 복사본에 `[Search evidence policy for this turn]` 정책을 보강한다. 이 블록은 사용자 원문이나 출처 근거가 아닌 서버 정책이며 원래 질문의 답변 언어·명시적 언어 요청을 유지한다. JSON 자료는 계속 비신뢰 데이터이고 지시·도구 사용·개인 정보 공개를 허용할 수 없다. 원본 DB 메시지·과거 대화·요약은 바꾸지 않는다.

최신 주장에는 질문의 대상과 관련 시점·현재 상태가 맞는 직접 근거를 요구한다. 그런 근거가 없으면 답변 처음부터 현재 정보를 확인할 수 없다고 밝히고 실제 제공된 출처가 뒷받침하는 내용만 인용한다. 목록의 첫 항목·가장 큰 버전 번호·조회 시각으로 최신 상태를 추정하지 않는다. 현재 사실을 먼저 단정한 뒤 주의 문구로 철회하거나, 미확인 현실 정보·대체 사이트·명령·확인 방법을 덧붙이지 않도록 한다.

구매 추천은 다음 세 규칙으로 예산·근거·답변 범위를 구분한다.

1. 사용자가 다르게 지정하지 않으면 예산은 상한이다. 예산보다 저렴한 가격도 조건을 충족하며 정확히 같은 가격일 필요는 없다. 자료의 대략적인 가격대는 근삿값으로 유지하고 사용자가 요청한 조건만 검사한다.
2. 인용된 모델명·가격·사양을 사용한다. 그 사양에 근거한 적합성은 평가임을 밝혀 설명할 수 있으며 자료에 사용자의 용도 문구가 똑같이 있을 필요는 없다. 확인되지 않은 사양·상위 구성·선택 사양·가격은 추정하지 않는다. 일반적인 구매 권장 조건을 개별 제품에서 검증된 속성으로 취급하지 않는다.
3. 기본적으로 예산과 관련 사양의 인용 근거가 가장 분명한 제품 하나를 골라 모델·확인 가격·관련 사양·추천 이유를 짧게 담는다. 검색 결과의 첫 항목이라는 이유로 우선하지 않으며 약한 후보로 개수를 채우지 않는다. 명시적인 복수 추천·비교·상세도 요청은 우선하고 요청하지 않은 일반 가이드·반복 결론은 생략한다. 조건을 충족하는 제품이 없으면 부족한 근거를 한 문장으로 알리고 끝내며 대안·확인 방법을 덧붙이지 않는다.

출력 상한을 늘리거나 답변이 정상 종료됐다는 사실만으로 근거 해석 오류까지 해결됐다고 판단하지 않는다.

서비스의 자료 적합화와 독립 평가가 같은 근거 입력 조합 함수를 사용한다. 서비스는 자료와 마지막 질문 뒤의 정책까지 포함한 실제 입력 토큰을 계산하고 기존 문자·문맥·잔여 예산 안에서 자료 수와 답변 상한을 줄인다. 공간을 확보하지 못하면 기존 검색 자료 미제공 안내로 전환하며, 그 안내도 들어가지 않으면 생성을 거부한다. 모델 입력에서 정책을 누락해 한도를 맞추지 않는다.

새 검색 근거를 제공하지 못한 경우 서비스와 독립 평가가 같은 조건부 안내를 사용한다. `self_contained_or_notice`는 외부 검색 근거가 없다는 상태이며 모든 답변을 금지하는 상태가 아니다. 제공된 글·고정 수치·검증된 로컬 계산 결과만으로 완결되는 작업과 일상 대화에는 정상 답변한다. 외부 사실 확인이 필요한 부분은 **이번 응답에 요청 정보를 검증할 검색 근거가 없다는 한 가지 의미**만 원래 요청의 답변 언어로 한 문장 전달한다. 특정 언어의 완성 문장을 복사하도록 하지 않으며 주제명을 반복하거나 안내 문장을 추가하지 않는다. 그 부분에 설명·예시·버전·인물·가격·사이트명·링크·명령·추천·확인 방법을 추가하지 않는다. 혼합 요청은 독립적으로 처리할 수 있는 제공 자료 작업을 계속 수행한다.

`no_query`는 `ask_subject`로 구분해 어떤 회사·제품·지역인지 짧게 묻는 기존 안내를 유지한다. 어느 경우에도 검색 기능 자체가 없다고 단정하거나 대상을 임의로 정하지 않는다. 검색이 불필요한 `not_needed`에는 검색 실패 안내를 넣지 않는다.

`build_search_fallback_messages()`는 입력을 복사하고 마지막 사용자 메시지의 답변용 복사본에 서버가 확인한 검색 상태를 덧붙인다. 메타데이터는 사유·근거 유무·답변 방식을 나타내며 사용자 원문의 일부가 아니라고 구분한다. 답변 언어는 명시적 언어 요청을 포함한 원래 질문에서 정하고 상태 블록의 언어로 바꾸지 않도록 한다. 저장된 원본 DB 메시지·과거 대화·압축 요약은 그대로 보존하며, 생성 실행에는 상태 안내가 포함된 실제 모델 입력을 기록한다.

서비스는 상태 안내가 포함된 입력의 실제 토큰 수를 다시 계산하고 남은 단계 예산과 모델 문맥에 맞춰 답변 상한을 조정한다. 안내와 최소 답변 공간이 한도에 들어가지 않으면 실행을 거부한다. 검색 상태를 버린 원래 질문만으로 답변을 생성하는 경로로 되돌아가지 않는다. 독립 평가는 같은 상태 입력을 사용하되 DB의 계정 잔여 예산·정산 통합까지 대신하지 않는다.

생성 승인 단계는 검색 후보나 명시적 검색 금지에 대한 안내가 추가될 수 있으면 OFF·로컬 전용·공급자 미설정이어도 그 입력 여유를 허용 상한에 포함한다. 일반 계정은 모델 문맥과 잔여 예산 중 작은 값을 요청의 허용 한도로 사용하고 시스템 계정은 모델 문맥 한도를 유지한다. 외부 검색 허가와 입력 안내를 넣을 공간은 서로 다른 조건이다. 이는 생성 전 토큰 예약·차감이 아니며 실제 입력을 다시 계산한 뒤 기존 완료·중단 후 정산을 따른다.

새 검색 결과를 우선 결합하되 출처별 조회 시각을 보존한다. 같은 검색어의 반복, 실패한 호출의 자동 반복, 기존 검색 횟수·시간·단계·문맥 한도 우회는 허용하지 않는다. 자료가 답변 문맥에 들어가지 못하면 기존 로컬 답변 경로로 돌아간다.

## 사용량과 운영

검색 판단·재검토의 확인된 실제 모델 사용량과 최종 답변의 실제 입력·출력을 완료·중단 후 한 번 정산한다. `not_needed`여도 이미 사용한 판단 토큰을 보존하고 남은 답변 출력 상한을 다시 맞춘다. 외부 검색 API 호출은 도구 실행으로 기록하며 API 비용을 모델 토큰으로 환산하지 않는다. 시스템 계정의 서비스 예산 면제·사용량 기록과 자동 압축의 별도 유지 작업·사용자 비차감 정책도 유지한다.

DB migration·환경변수·화면 설정·의존성은 추가하지 않는다. 이미 실행 중인 API·독립 worker는 사용자가 정상 재시작할 때 새 코드를 적용한다. 새 서버·원격 미리보기·외부 배포를 시작하지 않으며 PostgreSQL·FastAPI·모델 서버의 loopback 바인딩과 허용된 LAN 웹 접속 정책을 유지한다.

## 평가와 한계

`scripts/evaluate_search_quality.py`는 제품의 후보 규칙·검색어 검증·판단 입력·검색 참고 지침을 재사용하고, 별도 합성 평가셋에서 검색 준비부터 최종 답변까지 기록한다. 기본 명령과 `validate`는 무통신 자료 검증이다. `run`은 이미 실행 중인 loopback 모델과 고정 검색 응답을 사용하며, `--live-search --case`로 공개 질문을 명시한 경우에만 설정된 검색 공급자를 호출한다. 서비스 DB·사용자 사용량 장부는 사용하지 않는다.

별도 `search-self-contained-v1.json`의 4개 사례는 OFF·로컬 상태에서 계산·번역·기초 설명·일상 대화를 불필요하게 차단하지 않는지 평가한다. 원본 검색 평가 23개 사례와 분리해 버전 관리하며 점수나 통과 수를 합산하지 않는다. 이 부속 평가의 계산 답변은 모델이 생성하고 로컬 계산 검증 도구를 호출하지 않으므로 검산 도구·서비스 정산의 통합 검증으로 취급하지 않는다.

`search-fallback-language-v1.json`은 검색 불가 안내의 응답 언어를 확인하는 별도 7사례·24개 기준이다. 한국어 검색 금지·OFF·로컬·빈 결과의 기존 품질 기준을 보존하고 모든 사례에 필수 언어 기준을 둔다. 영어 질문, 한국어 질문의 명시적 영어 요청, 영어 질문의 명시적 스페인어 요청도 포함한다. 이 기준 추가는 원본 23사례를 변경하지 않으며 이전 품질 점수와 직접 비교하지 않는다. 실제 worker의 정산·SSE 통합 통과와 답변 언어의 의미 검증도 구분한다.

실제 공급자에서 받은 오래된 자료로 같은 오답이 재현되는지 확인할 때는 해당 응답을 로컬 고정 자료로 별도 재생한다. 이는 공급자를 다시 조회하는 실제 검색 평가와 다르며 원본 23개 사례의 점수에 합산하지 않는다. 공개 검색 요약 원문과 재생 자료는 `data/evaluations/`에 로컬 보존하고 버전 관리 문서에는 범위·관측 요약·URL·해시만 남긴다. 보강 코드를 추가했다는 사실과 고정 자료 재생·새 실제 검색·worker 통합 검증의 완료는 구분한다.

검색 판단은 생각하기 OFF로 실행하며 보고서의 `configuration.search.planning_thinking`과 `configuration.search.planning_sampling`에 판단 설정을 최종 답변 설정과 분리해 남긴다. 계획 프롬프트나 도구 샘플링 변경 전후를 비교할 때 이 차이와 실행 코드 해시를 함께 확인한다. 초기 실행에서 관측한 명시적 검색의 잘못된 `no_query`, 원문에 없는 부분문자열 조합, 도구 호출이 반환되지 않은 응답도 원래 보고서에 보존한다. 수정 후 성공한 실행으로 실패를 덮어쓰거나 실패 사례·채점 기준을 완화하지 않는다.

검색 여부·검색어 단어·인용 번호의 자동 진단은 의미 품질 점수가 아니다. 공통 [답변 채점 계약](../answer-quality-evaluation.md)에 따라 보존한 검색 자료와 답변을 함께 판독한다. AI 예비 판독과 사람 최종 채점·정식 기준선 승인을 구분한다. 합성 자료 실행과 실제 검색 실행도 별도 범위로 해석한다.

이 ADR은 구현과 평가 절차의 결정이며 성능 달성 기록이 아니다. 실제 모델·실제 검색을 실행하지 않은 조건, 채점하지 않은 답변, 사람 검토가 없는 예비 판독은 각각 미실행·미채점·검토 대기로 남긴다. DB 없는 평가는 서비스의 권한·모드 변경 경쟁·사용량 정산을 대신하지 않는다. 그 경계는 격리 DB 회귀 검사로 확인한다. 실행 명령·보고서 해석은 [검색 품질 평가 안내](../search-quality-evaluation.md)를 따른다.
