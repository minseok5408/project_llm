# ADR 0014: 문맥 검색·제한 재검색과 단계별 사용량

- 날짜: 2026-09-12 (실제 MLX 사전 검증: 2026-09-10)
- 상태: 구현
- 마이그레이션: `0013_generation_steps`
- 범위: TODO 최우선 2번과 3번

## 문제와 결정

기존 검색은 현재 질문 앞부분을 한 번 검색하고 최종 답변만 정산했다. 따라서 이전에 언급한 회사에 대해 “그 회사 최신 뉴스”라고 물으면 검색 대상을 해석하지 못하고, 검색 판단을 모델에 맡길 경우 추가 사용량을 기록할 수 없었다.

같은 독립 worker 안에서 검색 계획 → 검색 → 자료 검토 → 필요 시 재검색 → 답변을 순차 실행한다. 별도 모델 프로세스나 병렬 추론은 추가하지 않는다. MLX의 네이티브 도구 호출을 사용하며 서버가 등록한 `web_search`와 `finish_search`만 허용한다. 한 판단에는 완성된 호출 한 개만 받으며 ID·함수명·JSON 인자·원문 근거를 검증한다. 분할 호출 인자는 4,096자로 제한한다. 검색 응답은 자료형·크기·공개 HTTP URL을 확인한 `SearchResponse`로 취급한다.

## 외부 전송 범위

ADR 0011의 “현재 질문 앞부분만 전송” 정책을 문맥 검색에 한해 확장한다. 로컬 모델에는 현재 질문 앞부분 최대 1,000자와 최근 사용자 발언 최대 4개의 앞부분 각 1,000자를 제공한다. 개인 프로필·연락처·내부 메모로 감지되는 과거 발언은 후보에서 제외한다. 시스템 프롬프트·압축 요약·이전 assistant 답변은 검색어 후보에 넣지 않는다.

도구 인자는 발언 번호와 그 발언에 실제 존재하는 연속된 원문 표현이다. 서버가 원문 일치를 다시 검사하고 합쳐 최대 500자의 검색어를 만든다. 과거 발언에서 선택한 표현의 합계는 80자 이내다. 공개 회사·제품 이름 등 질문 해결에 필요한 표현만 고르도록 지시한다. 개인 정보 탐지는 보조 필터이며 모든 민감한 표현을 판별한다고 보장하지 않는다. 사용자가 외부 전송을 원치 않으면 기존 로컬 전용·검색 안 함 설정이 우선한다.

검색 결과는 다음 로컬 판단에 제목·요약만 제한해서 넣는다. 자료 안의 명령은 권한을 넓히지 못하며 새로운 외부 검색어도 사용자 발언에서 검증된 표현만 사용한다. 웹페이지 본문 수집·임의 URL 방문·새 외부 도구는 추가하지 않는다. 화면의 연결 및 검색 안내에도 문맥에서 필요한 표현이 전달됨을 표시한다.

## 실행 상한과 실패 처리

기본 검색은 최대 2회, 준비 반복은 총 90초, 판단 출력은 호출당 256토큰이다. 전체 단계는 최종 답변 포함 최대 8개이며 답변 한 단계와 최소 출력 공간을 남긴다. 같은 검색어는 공백·대소문자를 정규화해 반복을 막는다. API 오류나 잘못된 도구 호출을 자동 재시도하지 않는다. 모델이 자료 부족을 판단한 경우에만 다른 검색어로 재검색한다.

매 실행 전에 사용자·작업 공간 접근 권한과 생성 상태·중단·로컬 전용 revision을 확인하고 대기 중에도 감시한다. 모드가 바뀌면 진행 작업을 취소하고 로컬 답변으로 전환한다. 계정·대화 권한을 잃으면 답변을 종료한다. 검색 실패·시간 초과·예산 부족 시 이미 확보한 근거는 제한된 범위에서 활용하고, 근거가 없으면 최신 사실을 확인하지 못했다는 지침으로 답한다. 검색 자료는 실제 토큰 수를 다시 계산한 뒤 채택한다. 재검색의 새 자료를 우선하고 URL 중복을 제거하며 출처별 조회 시각을 보존한다.

## 사용량과 복구

`generation_steps`는 단계 UUID·생성 내 순번·모델/도구 구분·이름·호출 ID·상태·종료 사유·입출력 상한·확정 사용량·정산 기준을 기록한다. `meta.step` 이벤트는 원문 프롬프트·도구 인자·검색어를 복제하지 않고 상태와 사용량만 제공한다. 기존 접근 권한이 적용되는 SSE로 재생할 수 있으며 새로운 작업 메뉴를 노출하지 않는다.

사용자 토큰을 사전에 예약·차감하지 않는다. 생성 승인 때 정한 허용량 안에서 각 호출의 실제 입력과 최대 출력을 검사한다. 완료한 호출의 실제 사용량은 다음 호출의 허용량에서 제외하고, 사용량을 확인하지 못한 호출은 최대 허용량만큼 내부 실행 예산을 소모한 것으로 취급해 반복 우회를 막는다. 이는 사용자 청구가 아니다.

생성 종료·중단·실패 때 확인된 모든 모델 호출의 입출력을 기존 `token_reservations` 한 건에 합산해 한 번만 정산한다. 최종 답변 시작 전에 중단되어도 완료한 검색 판단 사용량은 남긴다. 사용자가 중단한 미완료 호출은 확인된 수신 토큰에만 기존 정산 규칙을 적용한다. 장애로 사용량을 확인할 수 없는 호출은 추정 청구하지 않는다. 최종 답변 사용량도 종료 이벤트보다 먼저 단계 기록에 저장해 복구 시 보존한다. `messages.token_count`는 해당 답변 출력만 나타낸다.

검색 API 호출은 별도 도구 단계이며 LLM 토큰으로 환산하거나 무료라고 표시하지 않는다. 시스템 계정의 서비스 예산 면제와 사용량 기록, 자동 압축의 별도 유지 작업 사용량·사용자 비차감은 유지한다. 종료 처리는 기존 생성·사용자 잠금과 멱등성을 유지한다. 실행 기록이 존재하면 migration downgrade는 기록을 조용히 삭제하지 않고 거부한다.

## 적용과 검증

기본 모델 Qwen3.8-27B와 현재 MLX 서버에서 도구 호출 및 실제 입력 토큰 일치를 확인해 기본 활성화한다. 다른 모델·서버를 사용할 때는 `WEB_SEARCH_AGENT_ENABLED=false`로 두고 검증 후 활성화한다. 필요한 메서드가 없는 공급자는 기존 단일 검색을 유지한다. 검증 명령은 `.venv/bin/python scripts/evaluate_search_tools.py`이며 이미 실행 중인 loopback 모델 서버에 합성 자료만 보내고 외부 검색·사용자 DB 변경·새 서버 실행은 하지 않는다.

자동 검사에는 원문 근거·인자·호출 크기, 단계별 합산과 중복 정산 방지, 검색 계획·외부 검색 중 중단, 모드 변경·권한 철회, 단계·토큰·시간 상한, 장애 복구를 포함한다. 실제 외부 검색 품질과 장문 대화의 검색 대상 해석 정확도는 이 계약 검증과 구분한다.

2026-09-12 검증: 백엔드 전체 644개 중 642개 통과 후 구버전 head 기대값 2개를 수정하고 해당 사례와 검색·정산 관련 총 14개를 재검증해 통과했다. 프런트 137개·TypeScript·lint·빌드와 격리 PostgreSQL migration 왕복·스키마 차이를 확인했다. 실제 MLX 합성 검증은 2026-09-10에 검색 대상 해석 778/56토큰, 검색 종료 819/28토큰으로 입력 계산 일치를 확인했고, 수신 도중 중단·후속 입력 계산도 통과했다. 개발 DB에 migration을 적용하고 기존 16개 테이블의 행 수 보존·신규 빈 테이블·스키마 일치를 확인한 뒤 기존 PostgreSQL을 정지 상태로 복원했다.
