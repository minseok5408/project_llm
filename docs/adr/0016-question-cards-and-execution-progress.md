# ADR 0016: 질문 카드와 내부 실행 진행 상태

- 날짜: 2026-09-12
- 상태: 채택
- 범위: 최우선 7번 중 4차 질문 카드·내부 실행 진행 상태. 본문의 진행 계획·처리 과정 목록은 후속 화면 정리에서 제거했다.

## 동작

필수 정보가 빠져 답변을 이어가기 어려운 경우 로컬 모델은 `ask_user_question`을 한 번 호출할 수 있다. 질문은 1~3개, 각 질문의 선택지는 없거나 서로 다른 2~4개이며 직접 입력을 항상 제공한다. 질문은 300자, 선택지는 100자, 사용자 답은 질문당 2,000자로 제한한다. 이미 있는 정보를 다시 묻지 않고 일반 요청에는 바로 답하도록 서버 지침을 추가한다.

유효한 카드가 만들어지면 질문을 assistant 원문에도 저장하고 해당 생성을 완료·정산한다. 기다리는 동안 worker나 모델 연결을 점유하지 않는다. 사용자는 카드에 답하거나 일반 메시지를 보내 대화를 계속할 수 있다. 카드 응답은 새로운 사용자 메시지·생성으로 남으며 원래 질문과 이전 답변은 보존한다.

내부 진행 상태는 문맥 준비와 응답 작성으로 시작한다. 실제로 실행한 압축·검색어 구성·검색·자료 검토·로컬 참고 확인을 실행자가 추가하고 상태를 갱신한다. 모델이 임의로 완료했다고 쓴 문장은 진행 상태를 바꾸지 않는다. 실패·중단·실행 안 함을 완료와 구분해 기록하며, 생성 중과 완료 후 모두 진행 계획·처리 과정 목록을 화면에 표시하지 않는다. 내부 상태·SSE 복원·단계별 사용량 정산은 유지한다. 숨겨 둔 상단 작업 메뉴와 입력창 아래 문맥 메뉴는 복원하지 않는다.

## 저장·승인

`0015_question_progress`는 `generation_runs.progress`와 nullable `question_card` JSONB 필드를 추가한다. 새 테이블 없이 질문·응답·이어지는 생성 ID와 진행 상태를 보존한다. 이전 생성에는 빈 진행 목록과 카드 없음이 기본값이며 과거 실행을 추정하지 않는다. 카드 이력이 있으면 이를 잃는 자동 downgrade를 거부한다.

`POST /api/v1/generations/{id}/respond`는 `answers`, 현재 생성 옵션·검색 정책과 UUID `Idempotency-Key`를 받는다. 웹 화면은 데이터 사용 ON일 때 `auto/on`, OFF 또는 설정 확인·저장 중과 오류 때 `local/off`를 전송한다. 질문 본문·사용자 ID·도구 권한은 클라이언트에서 받지 않는다. 세션·CSRF·Origin·작업 공간 소속·생성 소유자·최신 질문의 현재 답변·완료 여부·기억 세대를 검사한다. 이미 응답한 카드, 재생성된 카드, 이후 메시지가 생긴 카드, 보관된 대화는 거절한다.

질문 응답 표시와 새 사용자 메시지·생성 승인은 같은 트랜잭션에서 커밋한다. 같은 요청 키의 재시도는 기존 생성을 반환한다. 다른 키로 동시에 응답해도 한 번만 승인하며 한도·권한·검증 실패는 카드를 응답 완료로 바꾸지 않는다. 답변 보내기는 다른 생성이 진행 중일 때 차단하되 입력은 가능하다. 미전송 카드 입력과 일반 초안은 대화별 메모리에 보관하며 새로고침·로그아웃 시 초기화한다.

메시지 조회에는 `question_card`, `can_respond`, `progress`를, 생성 조회와 `meta`·종료 이벤트에는 내부 진행 목록을 포함한다. 새로고침·연결 재생으로 같은 상태를 복원하되 진행 목록은 화면에 렌더링하지 않는다. 원래 질문을 복사하거나 이후 문맥으로 사용할 때는 저장된 assistant 원문을 사용한다.

## 모델·정산·권한 경계

질문 판단용 별도 추론 호출은 추가하지 않는다. 최종 응답 호출에 질문 도구만 등록하며 같은 도구 template로 실제 입력량을 다시 계산한다. 문맥·허용 토큰 안에서 출력 상한을 조정한다. 도구 미지원 공급자, tokenizer 미지원, 도구 입력을 넣을 공간 부족에서는 일반 답변으로 계속한다. `GENERATION_QUESTIONS_ENABLED=false`로 질문 카드 기능을 끌 수 있다.

정상 카드도 한 번의 모델 응답이므로 `generation_steps`의 실제 입력·출력 사용량을 기존 후정산으로 기록한다. 시스템 계정의 예산 면제, 사용량 기록과 사용자 중단 시 확인 수신량 정산을 유지한다. 잘못된 도구명·인자·불완전 호출·잘못된 사용량은 조작 가능한 카드로 노출하지 않는다. 유효하게 확인된 사용량만 정산한다.

카드 응답은 정보 제공이며 검색 권한 승인이 아니다. 서버의 사용자별 데이터 사용 설정(`local_only`)과 현재 요청의 검색 정책이 계속 우선한다. 내부 진행 상태도 권한을 늘리지 않는다. 파일 업로드·RAG, 임의 셸·파일 실행, 모델이 작성하는 범용 작업 목록 편집은 이번 범위에 포함하지 않는다.

새 사용자 메시지에는 사용자가 입력·선택한 답과 질문 번호만 저장한다. 모델이 작성한 질문 본문은 이전 assistant 원문으로 참고하며 사용자 발언에 복제하지 않는다. 기억에서 나온 질문 표현이 이후 외부 검색의 사용자 발언 후보로 바뀌지 않게 한다.

## 검증

실제 PostgreSQL에서 카드 완료·응답·동시 승인·재시도·오래된 카드 거절·권한·CSRF·한도·중단·확정 사용량·복원과 migration 왕복·스키마 일치를 검사한다. 프런트는 선택·직접 입력·미입력 전송 차단·실패 재시도 키와 내부 진행 상태·종료 복원을 검사한다. 생성 중·완료 후 처리 과정 미표시와 답변 본문·질문 카드 유지도 검사한다. 기존 로컬 개발 화면의 임시 합성 페이지에서 데스크톱과 375px 모바일 배치, 입력·응답 후 표시를 확인한 뒤 검증 페이지를 제거한다. 최종 검사 수치는 개발 현황에 기록한다.

웹 중계는 명시적으로 받은 세션 쿠키·CSRF만 전달하고 fetch 자동 인증 재시도를 끈다. Node 24.15.0에서는 출처 없는 스트림 본문이 401 인증 재시도 경로에 들어가 `expected non-null body source` 연결 오류와 502로 바뀌었다. `credentials: omit`을 사용해 원래 401·Set-Cookie를 보존하며, 명시적으로 전달한 쿠키가 유지되는지 실제 loopback HTTP 회귀 테스트로 검사한다.
