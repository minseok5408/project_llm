## 최근 채팅 UI 개선

사용자가 승인한 여섯 UI 개선을 구현했다. 대화 행의 관리 메뉴와 제목 변경·삭제 확인창은 현재 열린 채팅과 별도의 대상 ID를 사용한다. 모바일 사이드바는 Base UI Dialog로 배경 조작·초점을 관리하며 닫은 뒤 시작점으로 복귀한다. 긴 사용자 메시지는 600자 또는 8줄을 넘으면 접고, 입력창은 같은 입력 요소를 유지한 채 확대·축소한다.

코드 블록은 언어 표시·원문 복사를 유지하면서 구문 색상과 줄바꿈 토글을 제공한다. lowlight 3.3.0·highlight.js 11.11.2를 로컬 동적 청크로 불러오며 이번 빌드의 코드 청크 gzip 크기는 약 28KB다. SSR은 즉시 평문을 출력하고 150ms 동안 내용이 바뀌지 않으면 20,000자·500줄 안의 지원 언어만 색칠한다. 미지원 언어·상한 초과·로딩 실패는 원문 전체를 평문으로 유지한다.

같은 질문의 인접한 답변 버전은 `user_message_id`로 묶고 이전/다음 버튼으로 전환한다. 화면에서 고른 버전이 DB의 현재 답변·다음 문맥을 바꾸지 않는다. 검색 결과에는 가장 최근 일치 메시지의 최대 282자 발췌와 강조를 표시하고, 선택하면 주변 최대 50개 메시지를 받아 정확한 메시지·답변 버전을 펼쳐 이동한다. 앞뒤 페이지를 이어 읽으며 권한 밖 대화·삭제된 메시지 위치는 노출하지 않는다. [ADR 0021](adr/0021-chat-ui-navigation.md)

프런트 **205개**, 검색·대화·저장소 관련 PostgreSQL **43개**가 통과했다. 격리 DB의 migration 왕복·스키마 비교, TypeScript·Oxlint·Ruff·변경 파일 형식·공백 검사와 프로덕션 빌드도 통과했다. 전체 백엔드를 재실행한 수치는 아니다.

실제 Headless Chrome의 합성 화면에서 390×900·1280×900 크기 각각 **21개**의 입력 확대·원문 보존·IME 이벤트·답변 버전·검색 선택 동작을 검증했다. 두 크기 모두 문서 폭과 스크롤 폭이 일치했고 스크린샷도 확인했다. 별도의 사이드바 합성 화면에서는 실제 프레임·애니메이션과 1100↔390px 전환으로 관리 대상·중복 제출·오류 후 재시도·모바일 초점·중첩 설정·화면 폭 전환 **25개**를 검사했다. 실제 계정으로 전체 앱을 사용하거나 실제 모바일 기기의 키보드를 조작한 검사는 아니다. 임시 DB를 정리했고 새 개발 서버·실제 계정의 변경·실제 모델 추론은 수행하지 않았다. 이번 개선에는 DB migration·환경 설정 변경이 없다.

## 최근 검색 조건 보정

데이터 사용 ON을 강제 검색에 연결하던 요청을 `local_only=false`와 `network_mode=auto`·`web_search=auto`로 보정했다. OFF와 설정 조회·재확인·저장 중·오류는 기존 `local/off`를 유지한다. 검색 키워드가 없는 인사·기초 개념·단순 번역·계산은 검색 준비·외부 검색을 생략하고 명시 검색·최신 뉴스·날씨·환율은 기존 자동 규칙에 따라 검색 대상으로 고른다. 이후 계획·예산·검색 서비스 상태와 로컬 답변 전환 정책은 그대로다.

첫 판단은 기존 키워드 규칙이며 “오늘 날씨가 좋다를 번역해 줘” 같은 요청은 오판할 수 있다. 모든 질문의 의미를 판별하는 모델을 추가한 것이 아니다. DB·환경 설정을 바꾸거나 새 서버를 실행하지 않는다. [ADR 0011](adr/0011-online-local-web-search.md)

검색 조건·생성·검색 에이전트·검색 서비스 백엔드 검사 **100개**와 프런트 검사 **171개**가 통과했다. 인사·기초 개념·단순 번역·계산에서 연결 확인·검색 계획 호출·외부 검색이 없고 답변 단계만 생성됨을 확인했으며 기존 최신 정보 검색·검색 금지·OFF 검사를 함께 통과했다. 격리 PostgreSQL의 migration 왕복·스키마 비교, TypeScript·Oxlint·Ruff·변경 파일 형식·공백 검사도 통과하고 임시 DB를 정리했다. 검색·모델 공급자는 테스트 대역을 사용했으며 실제 검색 서비스 호출이나 모델의 의미 판단 품질을 평가한 결과는 아니다.

## 최근 DB 역할 정리

중복 첨부 연결을 제거하고 `documents`를 대화별 활성 파일의 기준으로 사용한다. `document_versions`는 문서당 하나만 허용하며 원본·검색 조각·처리 상태와 파서·임베딩·스캐너 이력을 유지한다. 확장자로 복원 가능한 MIME 저장만 제거하고 업로드 입력 검증은 유지한다. 사용하지 않는 `conversations.settings`·`messages.prompt_version`을 제거하고 생성 옵션은 `thinking`과 기존 `max_output_tokens`로 저장한다. 외부 API의 `options` 형식은 바꾸지 않는다.

생성과 메시지·압축 요약은 같은 대화, 생성과 정산 기록은 같은 사용자로 연결되도록 복합 외래 키를 보강했다. 참조 대상의 복합 unique 3개는 이 경계를 DB에서 검증하기 위해 유지한다. 플랫폼·작업 공간·메시지 역할, 예산 스냅샷·사용 누계·기존 예약과 후정산 상한, 압축 버전·별도 사용량, 원문·출처·의존성은 제거하지 않는다. [ADR 0020](adr/0020-schema-roles.md)

코드와 실제 개발 DB의 migration head는 `0017_schema_roles`, 도메인·관측 테이블은 **21개**다. migration은 진행 생성, 비어 있지 않은 미사용 필드, 알 수 없거나 상충하는 생성 옵션, 문서와 첨부 범위 불일치, 여러 문서 버전, 복원할 수 없는 MIME 이력이 있으면 적용을 거부한다. 기존 데이터를 임의로 삭제하거나 의미를 추정해 바꾸지 않는다. 다운그레이드는 기존 옵션·첨부 연결·기본 필드를 재구성한다.

실제 개발 DB 적용 전후 보존 대상 21개 테이블의 모든 행 해시가 일치했다. 사용자 6명·대화 31개·메시지 129개·생성 65개·정산 65개·이벤트 15,870개를 보존했다. 적용 전 백업은 `data/backups/before-schema-roles-20260912T204727-090761c1.dump`에 보관했다(0600, 847,137바이트). 임시 복제 DB에서 백업을 복원하고 upgrade→downgrade→upgrade를 실행해 보존 행 해시 일치·스키마 차이 없음을 확인한 뒤 복제 DB를 삭제했다.

관련 PostgreSQL 검사 **108개**(79.55초)와 프런트 **171개**가 통과했다. 전체 백엔드 **757개** 중 756개가 통과했고(301.38초), 이전 스키마의 두 기본 컬럼까지 비교하던 데이터 보존 검사 1개의 기대값을 갱신했다. 제거 전 값이 `{}`·NULL인지 확인하고 나머지 원문·식별자·시각 비교는 유지했으며, 해당 검사와 스키마 왕복·손실 방지·참조 무결성 **13개**를 재실행해 모두 통과했다(16.35초). 최종 재검사 후 애플리케이션·마이그레이션 코드는 바꾸지 않았다. 격리 migration 왕복·스키마 비교·Ruff·변경 파일 형식·공백 검사를 통과하고 임시 DB를 정리했다. 실제 브라우저 조작이나 모델 추론 품질 검사는 이번 DB 정리 범위에 포함하지 않았다.

적용 직전 진행 생성은 0건이었고 실제 앱은 이미 종료된 상태였다. 새 서버 실행·프로세스 재시작·`.env` 변경은 하지 않았다. 아래 날짜별 검사 수와 당시 DB 상태는 과거 기록으로 유지한다.

## 최근 역할 분리

대화 세션은 사용자 요청을 제어하고 파일 처리·생성 스트림을 조합한다. 첨부 요청과 폴링은 `ConversationFiles`, SSE 연결·재연결·중단은 `GenerationStream`, 이벤트 검증과 상태 변경분 계산은 `generation-events.ts`로 분리했다. 공통 요청 자료형과 오류 처리는 `lib/http.ts`에 두고 기존 세션의 공개 메서드·자료형 import를 유지한다.

Workbench의 스크롤·이전 메시지 복원, 계정별 저장소와 라우팅·화면 복귀, 모델 상태 폴링, WebMCP, 메뉴·초점, 모션 구독을 여섯 훅으로 분리했다. Workbench에는 화면 조합과 사용자 행동 연결을 남겼다. 저장소는 명시적 `Repository` 진입점과 권한·계정·대화·메시지·검증·커서·오류 기록으로 나눴다. 대화·첨부 삭제는 `ConversationService`가 같은 트랜잭션으로 조합한다.

생성 준비 단계는 `GenerationJob` 작업 스냅샷과 DB·모델 공급자·설정만 담은 `ModelExecution`을 받는다. worker가 단계 실행을 조합하고 승인·중단·정산은 기존 책임을 유지한다. 기능·API·DB 스키마·환경 설정을 바꾸지 않았으며 실제 개발 DB·`.env`를 수정하거나 새 개발 서버를 시작하지 않았다. 현재 경로와 결정은 [프로젝트 구조](../tree.md), [ADR 0019](adr/0019-responsibility-separation.md)를 따른다.

전체 프런트 **171개**, 격리 PostgreSQL을 포함한 전체 백엔드 **741개**(300.07초)가 통과했다. migration 왕복·스키마 차이 없음, TypeScript·oxlint·Ruff·변경 파일 포맷·공백 검사·프로덕션 빌드를 확인하고 임시 DB를 정리했다. 파일 정리 실패 시 대화 삭제까지 롤백되는 회귀 검사와 계정 종료 뒤 늦은 응답·브라우저 이벤트 해제를 검증했다. 분리 전후 저장소의 권한·잠금·SQL 본문과 생성 이벤트 조합 3,240개의 결과도 비교했다. 실제 브라우저 조작·MLX 추론·외부 검색 품질 검사는 이번 역할 분리 범위에 포함하지 않았다.

## 최근 화면·환경 정리

다음은 앞선 화면·환경 정리 시점의 기록이다. 데이터 사용 ON의 현재 요청 매핑은 위 검색 조건 보정을 따른다.

설정의 **데이터 사용 ON/OFF** 하나로 외부 검색을 제어하고 별도 웹검색 선택을 제거했다. ON은 사용자별 `local_only=false`와 생성 요청 `auto/on`, OFF는 `local_only=true`와 `local/off`로 연결한다. 설정 조회·재확인·저장 중과 오류 때도 `local/off`로 보낸다. ON이어도 검색 계획·예산·검색 서비스 상태에 따라 검색 자료 없이 기존 로컬 답변을 이어갈 수 있다. [ADR 0011](adr/0011-online-local-web-search.md)

답변 본문의 **진행 계획·처리 과정 목록**을 제거했다. 질문 카드와 내부 진행 상태·SSE 복원·생성 단계별 실제 사용량 정산은 유지한다. [ADR 0016](adr/0016-question-cards-and-execution-progress.md)

실제 `.env`에 누락된 13개 키를 추가하고 기존 37개 값과 0600 파일 권한을 보존했다. 앞으로 `.env.example`에 새 키를 추가할 때 실제 `.env`에도 함께 반영하도록 [프로젝트 작업 규칙](../AGENTS.md)에 기록했다. 기존 비밀값과 사용자 지정 값은 유지한다.

이번 화면·환경 정리는 프런트 전체 **162개**, 데이터 사용 관련 백엔드 **18개**가 통과했다. 백엔드는 관련 범위 검사이며 30개는 범위 밖으로 제외했다. 격리 DB의 migration 왕복·스키마 차이 없음, TypeScript·oxlint·변경 파일 oxfmt·프로덕션 빌드·공백 검사를 확인했다. 개발 DB와 실행 중 서버는 변경하거나 재시작하지 않았고 임시 테스트 DB는 정리했다.

## 최근 6차 개발

현재 질문·입력 언어로 답하며, 명시적 번역·다른 언어 요청은 해당 답변에 우선 적용한다. 다음 질문에는 그 입력 언어를 사용하며 이전 번역 요청이나 다른 언어 자료를 언어 지시로 계속 적용하지 않는다. 요청하지 않은 중국어 혼용을 억제하고 인용·코드·고유명사는 보존한다. 저장 원문·외부 검색 후보를 바꾸지 않고 실제 입력 토큰에 언어 안내를 포함한다. [ADR 0018](adr/0018-answer-language-policy.md)

최종 정책으로 언어·문맥·압축 검사 76개, 입력 계산·공급자 검사 80개, 검색·정산 검사 12개와 별도 worker 프로세스 검사 3개가 통과했다. 전체 백엔드 검사에서는 737개가 통과하고 3개가 실패했으며, 고정 예산 대신 실제 기본 답변 입력량을 기준으로 테스트를 보완하고 동일한 정책으로 부모·자식 프로세스를 다시 실행해 위 관련 검사에서 모두 해소했다. 프런트 전체 158개와 이어 쓰기 보완 후 채팅 검사 79개, TypeScript·lint·빌드가 통과했다.

실제 MLX의 [12개 표본](evaluations/answer-language-smoke.json)에서 한국어·영어 입력, 양방향 번역과 다음 질문의 언어 복귀, 잘린 영어 답변 이어 쓰기, 일반·깊이 생각하기의 언어 유지와 코드·인용 보존을 확인했다. 모든 호출에서 입력 토큰 계산과 실제 사용량이 일치했다. 질문 도구를 허용한 영어 요청에는 영어 확인 질문이 일반 본문으로 나왔으며, 실제 모델의 카드 생성까지 확인한 표본은 아니다. 카드 저장·응답 언어 보존은 서버 검사로 확인했다.

DB head는 `0016_local_file_rag`이며 도메인·관측 테이블은 22개다. 기존 테이블 행 수와 언어 필드 이외의 사용자 설정·생성 이력을 보존했고 스키마 차이가 없다. 독립 worker에는 앱 정상 재시작이 필요하다.

## 이전 5차 개발

대화별 파일 첨부·상태·재시도·삭제, 로컬 다국어 검색, 페이지/조각 근거와 원본 다운로드를 추가했다. PDF·TXT·Markdown·CSV·JSON을 지원한다. 다른 작업 공간/대화는 검색 후보에서 제외하고 파일 삭제 시 원본·벡터·파생 문맥을 회수 또는 무효화한다. [ADR 0017](adr/0017-local-file-rag.md)

전체 백엔드 719개(284.71초), 최종 API 보완 3개, 프런트 157개, TypeScript·lint·빌드가 통과했다. 실제 sandbox, 한국어 문서 검색 비교(12문항), 실제 MLX의 근거·주입 지시 무시/447 입력·24 출력 토큰 일치, 기존 개발 화면의 데스크톱·375px 입력/재시도/삭제를 확인했다. 개발 DB는 `0016_local_file_rag`, 기존 18개 테이블 행 수 보존·총 22개·drift 없음이다. 로컬 임베딩 설치는 완료했으며 독립 worker 반영에는 앱 재시작이 필요하다.

스캔 PDF OCR·DOCX는 지원하지 않는다. 실제 ClamAV 엔진 운영, 자동 백업/복원·미참조 원본 청소와 광범위한 문서 검색 평가는 후속 항목이다. 6차 입력 언어에 따른 답변 정책은 위 최근 변경에 기록했다.

코드와 실제 개발 DB의 마이그레이션 head는 `0017_schema_roles`이며 도메인·관측 테이블은 21개다. 적용·보존 확인과 최종 검사 결과는 위 최근 DB 역할 정리를 따른다. 파일 메타데이터는 `documents`·`document_versions`·`chunks`에 보관한다. 개인 기억은 `user_memories`에 저장하고 답변·압축 요약에는 기억·문서 세대 의존성을 기록한다. 모델 호출별 사용량과 검색 도구 실행을 `generation_steps`에 기록한다.

2차는 최우선 2번+3번을 완료했다. 문맥 검색·재검색을 기본 활성화하고 단계별 실행·확정 사용량을 같은 worker에서 기록한다. 2026-09-12 개발 DB에 `0013_generation_steps`를 적용했으며 기존 테이블의 행 수와 스키마 일치를 확인했다. 적용 뒤 PostgreSQL은 원래의 정지 상태로 복원했다.

3차는 최우선 4번+5번을 구현했다. 설정에서 저장한 기억의 새 채팅 반영과 압축 이전 원문 회수를 추가했다. 개발 DB에 `0014_memory_recall`을 적용하고 기존 17개 테이블의 행 수 보존·18개 테이블 스키마 일치를 확인했다. 실행 중인 로컬 서버는 유지했다. 독립 worker에는 자동 reload가 없으므로 앱을 재시작해야 새 생성 문맥 구성이 적용된다.

4차는 질문 카드와 실행자 기준 진행 목록을 구현했다. `0015_question_progress` 적용 전 진행 생성 0건을 확인했고 기존 18개 테이블의 행 수를 보존했다. 새 서버는 실행하지 않았다. 독립 worker에는 앱 재시작 후 새 질문 도구가 적용된다.

## 출력 한도·컨텍스트·사용자 예산의 차이

| 구분                   | 기본값·정책                                             | 의미                                                                                              |
| ---------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 한 번의 답변 출력 상한 | 4,096토큰                                               | 이 길이에 도달하면 해당 생성이 종료될 수 있다. 화면은 숫자를 전송하지 않고 서버 기본값을 사용한다 |
| 모델 컨텍스트          | 32,768토큰                                              | 한 요청에 사용하는 입력과 허용 출력의 합. `LLM_CONTEXT_WINDOW` 설정으로 관리한다                  |
| 압축 시작 기준         | 입력 + 요청 최대 출력이 문맥의 75% 이상                 | 요약할 과거 대화가 있을 때 적용. 별도 문맥 문자 상한 초과도 압축 계기가 된다                      |
| 압축 목표              | 문맥의 55%                                              | 최근 원문 보존 수를 정하는 목표이며 항상 달성되는 보장은 없다                                     |
| 최근 원문              | 우선 4쌍, 최소 마지막 1쌍                               | 현재 질문과 함께 유지해 직전 답변을 이어 쓸 수 있게 한다                                          |
| 요약 출력 상한         | 1,024토큰                                               | 답변 상한과 별개. 작은 문맥에서는 컨텍스트의 1/4 이하로 제한한다                                  |
| 일반 사용자 예산       | 한국 시간 기준 월 무료 20,000토큰 또는 유효한 별도 플랜 | 생성 전에 예약·차감하지 않는다. 실제 답변의 확인된 입력·출력을 종료 후 정산한다                   |

서버는 남은 문맥 공간과 일반 사용자의 잔여 예산에 맞춰 실제 출력 상한을 줄인다. 상한 전체를 미리 소비하거나 청구하지 않는다. 요약 생성은 시스템 유지 작업으로 기록하고 사용자 예산에서 차감하지 않으며, 실제 답변에 사용한 요약문은 답변 입력 사용량에 포함한다.

`이어서 생성`은 저장된 부분 답변을 문맥으로 삼아 **새 사용자 요청과 새 답변**을 만든다. 기존 답변과 작성 중인 입력은 보존한다. 자동으로 무한 재실행하지 않으며, 새 답변에도 출력 상한과 기존 정산 정책이 적용된다. 명시적인 `finish_reason=length`를 근거로 안내하고, 출력 토큰 수가 상한과 같다는 이유만으로 중단을 추정하지 않는다.

## 현재 한계

- **자동 압축이 무제한 문맥을 제공하지는 않는다.** 새 질문 또는 마지막 원문 대화가 너무 크면 압축 전에 거절될 수 있다. 과거 한 쌍을 요약 입력에 넣을 수 없는 경우나 요약 후 문맥·예산이 부족한 경우에도 진행하지 못한다. 자세한 경계는 [압축 한계](adr/0009-context-compaction-and-continuation.md#자동-압축으로도-처리할-수-없는-경우)를 따른다.
- **원문 회수는 제한된 어휘 검색이다.** 과거 내용을 묻는 표현·코드 식별자에서 같은 대화 원문을 회수하며, 의미가 비슷한 표현을 모두 찾지는 않는다. 개인 기억은 설정에서 직접 저장한 내용만 새 대화에 전달하고 입력 한도에 따라 일부를 생략할 수 있다.
- **긴 답변의 완성을 보장하지 않는다.** 이어서 생성도 상한에 도달할 수 있고, 실제 모델이 불필요하게 반복하거나 일찍 종료하는 품질 문제는 별도 평가가 필요하다.
- **초안·완료 알림은 현재 계정 세션의 메모리에만 보관한다.** 대화 이동 때는 유지하지만 새로고침·로그아웃 때 초기화한다. 서버 대화·생성·문맥 측정값은 다시 복원한다. 과거 생성에 새 문맥 측정 기록이 없으면 수치를 추정하지 않는다.
- **범용 도구 반복 실행·메시지 편집 분기는 미완료다.** 현재 도구는 등록된 웹검색·검색 종료 판단·질문 카드와 로컬 원문/기억·첨부 파일 검색으로 제한한다. 임의 셸·파일 도구와 범용 반복 실행은 추가하지 않았다.
- **운영 확장에는 후속 작업이 남아 있다.** 이메일 확인·비밀번호 재설정 메일·실제 결제·감사·백업 복구 등은 TODO에서 관리한다. 외부 배포·원격 미리보기는 현재 범위에 포함하지 않는다.
