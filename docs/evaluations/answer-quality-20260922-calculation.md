# 2026-09-22 계산·코드 오답 개선과 재평가

일반 모드에 로컬 산술 검산과 제한된 Python 원문 추적을 연결한 뒤, 기존 24문항을 각 3회 다시 실행했다. **72/72 정상 생성, AI 예비 채점 390/402점(97.01%), 응답 72/72 통과, 필수 0점 0건**이다. 최초 결과의 378/402점·66/72 통과·필수 0점 6건에서 개선됐다. 기존 질문·67개 기준·0.90/0.75 통과선은 변경하지 않았다.

이는 Codex의 독립 분담 판독과 교차 검토 결과다. 사람 최종 채점과 정식 운영 기준선 선정은 남아 있다. 최초 불합격 결과를 통과 기준선으로 간주하는 `compare`를 실행하지 않고, 같은 기준의 관측 차이를 따로 기록했다. 기존 기준 대비 점수가 내려간 사례는 없다.

최종 [전체 답변·실제 입력·도구 기록·AI 판독·운영 검사](answer-quality-20260922-calculation-final-r3-ai.json), [최초 실패 기록](answer-quality-20260922.md), [중간 진단 원자료](answer-quality-20260922-calculation-diagnostics.json)를 보존했다. 개선 후 보고서에는 실행 코드 해시와 변경 중인 작업 트리 상태를 남겼으며, 실행 중 평가 대상 소스가 바뀌지 않았음을 확인했다.

기존과 답변이 달라진 것은 할인·주문 수량·코드 출력의 9응답이다. 나머지 63응답은 질문·최종 입력·답변이 기존과 같아 같은 점수와 근거를 유지했다. loopback 명시 누락, 코드 설명의 영어 용어 풀이, 계약서 첨부 안내 누락, 거절문의 장황함은 여전히 부분 감점이다. 모호한 언어 기준은 사람 검토 대상으로 남긴다.

## 개선 방식과 실행 조건

산술 질문은 로컬 모델이 식 하나를 계획하고 제한된 Decimal 해석기가 실제 값을 구한다. 질문 수치와의 연결을 검사하여 추측한 답 하나나 `추측값 + 0`을 검산으로 처리하지 않는다. Python 출력 질문은 모델의 계획 호출 없이 질문의 완전한 코드 원문을 제한 AST 해석기로 추적한다. 임의 Python 실행·파일·네트워크·import는 지원하지 않는다. 검증 범위와 실패 정책은 [ADR 0023](../adr/0023-local-calculation-verification.md)을 따른다.

최종 답변은 일반 모드, 모델 Qwen3.8-27B-4bit, 문맥 32,768, 출력 상한 512, 사례 제한 120초, 동시성 1을 유지했다. 기존 temperature 0.7·top_p 0.8·top_k 20·presence_penalty 1.5를 바꾸지 않았다. 정답·채점표는 모델에 전달하지 않았다. 고정 자료 SHA-256은 `2353085bd635f6f0b99b97d8d0c6031b99db968926dc7b2723f76b41462a46fe`다.

요청의 seed는 생략했고 설치 서버 mlx-vlm 0.6.17의 기본 seed는 0이다. 각 사례의 3회 답변이 같으며 독립 무작위 표본의 품질 분산은 측정하지 않았다. 지침 강화·presence penalty 제거·greedy 진단에서는 오답이 남았고, 깊이 생각하기 진단은 맞혔지만 제품 기본 모드에는 적용하지 않았다. 이 진단 결과와 초기 도구 연결 결과도 위 원자료에 함께 남겼다.

## 실제 worker와 코드 검증

기존 loopback 모델과 일회용 PostgreSQL DB에서 실제 worker의 할인·코드 출력 **2개 검사를 통과**했다(62.90초). 기본 질문 도구를 켠 최종 생성에서도 48,400원과 5를 답했다. 할인은 일반 회원의 계획·답변 2,201토큰을 종료 후 한 번 정산했고, 코드는 시스템 계정의 1,291토큰을 기록하면서 예산 면제를 유지했다. 선차감 0, 로컬 추적 토큰 0, 중복 종료 재정산 없음, 완료 이벤트 1회, SSE 본문 일치, 외부 검색 0건도 확인했다. 검사 DB는 정리했다.

백엔드 전체 **1,079개**가 통과했으며, 마지막 설명 근거 보강까지 포함한 계산/검색 관련 PostgreSQL 회귀 **79개**, 해석기·평가 연결 회귀 **154개**가 통과했다. 수치는 서로 겹치므로 합산하지 않는다. AST 검사는 접근 차단·자원 제한·음수 나눗셈·지연 평가 등을 포함한다. Ruff·문서 형식·공백 검사도 수행했다. 프런트나 DB migration·환경변수 변경은 없다.

실행 중인 사용자 API·독립 worker를 재시작하지 않았다. 위 모델 평가는 새 프로세스로 읽은 수정 코드를 사용했고 실제 worker 검사는 격리 DB를 사용했다. 사용자 앱에는 정상 재시작 후 반영된다.

## 한계와 후속

추가 산술·코드 8문항은 최초 추가 실행 전에 별도 질문·기준으로 고정했다. [추가셋 실행·AI 판독](answer-quality-20260922-calculation-generalization-ai.json)은 출력 정답 **8/8, 16/16점**이다. 하지만 초기 실행에서는 `//`와 소수 몫을 혼동하는 표기, 후속 8문항 실행에서는 결과 부호가 피제수를 따른다는 잘못된 일반 설명이 있었다. 고정 출력 기준의 통과와 별개로 이 오류를 원자료에 보존했다.

이를 보완해 실제 `//` AST를 추적한 결과에 정수 나눗셈의 의미를 함께 넣었다. 자연어 질문의 정답이나 특정 숫자를 하드코딩하지 않았다. 음수 질문은 다시 실행하여 **음의 무한대 방향으로 내림**이라는 설명과 `[-3, -1, 0, 2]`를 모두 확인했다. 원래 코드 출력도 3회 모두 **5**였다. 보존한 도구 근거를 재조합해 기존 72회 중 나머지 69회와 추가 8문항 중 나머지 7문항은 입력이 변하지 않음을 확인했다. [마지막 영향 문항 4응답과 설명 검토](answer-quality-20260922-floor-followup-ai.json)를 앞선 전체 실행과 별도로 보존한다. 이전 72/8응답을 덮어쓰거나 다른 소스 버전의 응답을 한 실행처럼 합치지 않는다. 실제 worker 2개 검사는 이 마지막 의미 정보 추가 전의 전체 평가 코드로 수행했다.

첨부 표의 합계 300만원은 맞았지만 해당 사례의 현재 질문에는 숫자가 없어 계산 도구를 호출하지 않았다. 고정 첨부 문맥에 대한 답변 결과이며 첨부 검색·자료 계산기의 통합 검증을 뜻하지 않는다. 실제 검색, 장기 대화·기억·압축, 첨부 파싱·검색·인용의 품질은 새 순서 2~4번으로 남긴다. 지원하지 않는 코드·자연어 수식 해석·설명의 정확성과 장시간·동시 요청은 이번 합성 표본만으로 보장하지 않는다.

## 재현

```bash
.venv/bin/python scripts/evaluate_answers.py run --repeat 3 \
  --output data/evaluations/calculation-candidate-new.json \
  --review-template data/evaluations/calculation-candidate-new-review.json

.venv/bin/python scripts/evaluate_answers.py run \
  --dataset backend/evaluation/fixtures/arithmetic-code-generalization-v1.json \
  --output data/evaluations/calculation-additional-new.json
```

이미 실행 중인 loopback 모델만 사용한다. `run` 종료 성공은 채점 통과가 아니며 새 답변은 고정 기준으로 별도 채점한다. 도구 없는 최초 조건 재현에는 `--no-local-calculation`을 지정한다.
