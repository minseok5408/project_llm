# 2026-09-23 검색 품질 개선·검증 결과

현재 코드는 **r14**이며 마지막 구매 자료 재생 1사례가 **AI 예비 10/10점(100%)**으로 통과했다. 앞선 r11 실제 Tavily 4사례의 **3통과·1실패**와 그 구매 자료를 그대로 사용한 후속 1사례 통과는 별도 결과다. r14 관련 DB 회귀 **154개(49.47초)**·Ruff 전체·변경 Python 17개 포맷·공백 검사를 통과했다. **원본 23사례를 최종 소스로 전체 재실행하지 않았으며 사람 최종 검토·정식 운영 기준선도 미완료**다.

이 문서는 r3 전체 실행, 후속 영향 문항·부속 사례, 실제 검색과 기록 재생, worker 통합·언어 검증을 버전별로 보존한다. 검색 금지·OFF·로컬 전용에서 외부 요청을 막는 동작과, 검색하지 않은 최종 답변이 정확한지는 별도로 평가했다. 초기 검색 불가 안내의 미검증 보충부터 실제 구매 추천의 잘림·근거 해석 오류까지 실패 기록을 유지했다.

평가자는 Codex AI이며 각 채점 파일에 `review_kind=ai_preliminary`, `human_review_completed=false`, `official_baseline_eligible=false`를 기록했다. 사람의 최종 검토는 미완료다. 서로 다른 소스 버전·부분 사례의 점수를 합산하거나 성공한 답변만 골라 최종 평균을 만들지 않는다.

## r3: 전체 실행에서 확인한 실패

[r3 전체 답변·입력·검색 기록·AI 예비 채점](search-quality-20260923/search-quality-20260923-synthetic-r3-ai.json)을 기준으로 다음 실패를 확인했다. 원본 실행 파일명의 `synthetic-final`은 당시 실행 이름이며 최신 코드의 최종 통과를 의미하지 않는다.

- `explicit_no_search`, `search_off`, `network_local`: 검색 호출은 없었으나 최신 Python 인터프리터 버전의 확인 방법으로 미검증 명령·PyPI 경로 등을 제시해 답변 기준이 0점이었다. 확인 불가를 먼저 밝혔어도 잘못된 후속 안내는 정당화되지 않는다.
- `current_role`: 합성 자료가 실제 현직 인물을 확인할 수 없다고 명시했는데 학습 지식의 인물·시점을 덧붙였다. 현실의 사실 여부와 별개로 제공 근거 밖의 주장을 현재 답변의 근거로 대체해 답변·인용·최신성 기준이 실패했다.
- `purchase_recommendation`: 구매 추천을 `not_needed`로 판단해 검색하지 않았고 근거 없는 제품·성능·현재 가격을 제시했다. 출력이 `finish_reason=length`로 잘려 실행도 실패했으며 전체 점수는 `null`이다.

부분 감점도 보존했다. `public_followup`은 필요한 회사 이름 외의 과거 대화형 표현을 검색어에 포함했고, `empty_results`는 실제 빈 결과를 검색 기능 이용 불가처럼 설명했다. 오래된 자료·상충 자료에서 충분성 판단이 부정확하거나 같은 검색어가 다시 제안된 관찰은 고정 채점 기준과 별도로 남겼다. 실패를 없애기 위해 새 기준을 소급 적용하거나 기존 기준을 완화하지 않았다.

## r4: 검색 필요성과 직접 근거 지침 보강

판단 지침에 직책·가격·구매나 여행 추천은 “최신”이라는 단어가 없어도 검색이 필요하다고 명시했다. 검색 참고 지침 앞에는 변동 사실을 제공 자료의 직접 근거 범위로 제한하고, 학습 지식으로 대체·보충하지 않으며 합성·가상 자료의 한계를 유지하도록 했다. 새 검색 근거가 없으면 확인 불가를 짧게 안내하고 미검증 방법을 덧붙이지 않도록 보강했다.

[r4 핵심 3사례](search-quality-20260923/search-quality-20260923-r4-probe-ai.json)에서 명시적 검색 금지의 불필요한 안내가 사라졌고, 현직 인물 질문은 확인 불가로 답했으며, 구매 추천은 검색한 가상 제품 자료의 범위 안에서 답했다. 다만 현직 확인 불가 설명에 출처 번호가 빠져 인용 기준은 부분 점수였다. 핵심 사례의 개선이 모든 검색 불가 경로의 개선을 보장하지는 않았다.

[r4 영향 13사례](search-quality-20260923/search-quality-20260923-r4-impact-ai.json)에서는 `search_off`·`network_local`의 미검증 PyPI 안내가 남아 실패했다. 나머지 선택 사례는 예비 기준을 통과했지만 `public_followup`의 불필요한 과거 표현은 부분 감점으로 남았다. 중복 검색어 제안은 서버의 중복 방지로 추가 호출되지 않았으며 모델의 제안 정확성과 서버 제한의 동작을 구분했다.

## r5: 검색 불가 안내 강화 후에도 남은 오류

검색 근거가 없는 답변을 짧은 확인 불가 안내로 제한한 뒤 [r5 검색 불가 4사례](search-quality-20260923/search-quality-20260923-r5-fallback-ai.json)를 별도로 실행했다. 명시적 검색 금지와 빈 결과 사례는 예비 기준을 통과했다.

`search_off`와 `network_local`은 여전히 검색 설정 때문에 조회하지 않은 상황을 검색 기능 자체가 없는 것으로 설명했다. 검증되지 않은 링크·과거 버전·지원 정보를 추가하여 실패했다. 따라서 시스템 안내 문구를 강하게 만드는 것만으로 모든 상태에서 해결됐다고 결론 내리지 않았다. 앞선 r3·r4 답변과 이 실패 기록을 그대로 보존했다.

## r6~r8: 상태 입력 보강과 부분 재검사

검색 불가 상태를 시스템 안내에만 두지 않고 **마지막 사용자 메시지의 모델 입력 복사본**에도 서버가 확인한 메타데이터로 덧붙이도록 보강했다. 사유·근거 유무·답변 방식을 구분하며 이 블록은 사용자 원문이 아니고 답변 언어를 바꾸지 않는다고 명시한다. 저장된 원본 DB 메시지·과거 대화·요약은 수정하지 않는다. 생성 실행에는 실제로 사용한 입력을 보존하므로 원본 메시지와 실행 입력의 역할을 구분한다.

서비스는 상태 안내를 포함한 최종 입력 토큰을 다시 계산하고 현재 문맥·잔여 실행 예산 안에서 답변 공간을 확보한다. 안내를 포함할 수 없으면 해당 안내를 버린 원래 질문으로 답하지 않고 실행을 거부한다. 이 구조의 독립 평가와 실제 worker에서의 권한·정산 검증은 서로 다른 검사를 필요로 한다. 상세 결정은 [ADR 0024](../adr/0024-search-quality-and-intent.md), 실행 범위는 [검색 품질 평가 안내](../search-quality-evaluation.md)를 따른다.

계산 영향 사례는 별도 원본 답변 평가의 할인 계산이다. 준비 도구에 전달한 식과 검증 결과 **48,400원**이 최종 답변과 일치했다. 이 한 문항의 통과로 계산 전체나 검색 전체를 완료 처리하지 않는다. 위 모든 기록은 AI 예비 판독이며 사람 최종 검토와 정식 기준선은 없다. 서로 다른 자료·소스 버전·실행 범위의 점수를 합산하지 않는다.
